# IKOS 3.5.20 — 건전성 감사 추가 수정 (builtin 의미, denormal 비교)

v3.5.19 이후 추가로 지적된 2건을 수정한다. 1번은 반례로 재현했다. 2번은 규칙의
논리적 빈틈을 막는 예방적 수정이다(아래 참고).

함께 지적된 v3.5.17(외부 링크 전역을 상수로 보고 분기를 접음)은 수정하지 않았다. IKOS 값
분석도 같은 폐쇄 세계 가정을 쓴다. `main` 에서 시작하면 전역을 초기값으로 두고, 외부 함수가
전역을 쓰지 않는다고 본다. v3.5.17 은 문법적 증명을 이 기존 가정에 맞춘 것이므로, 우리
수정이 새 가정을 더한 것이 아니다.

---

## 1. `-fno-builtin` 의 sqrt/abs 에 표준 함수 의미 적용 (v3.5.8.3 등)

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

```c
double r = sqrt(4.0);                         /* -fno-builtin: 사용자 sqrt 일 수 있음 */
if (r > 3.0) { int z = 0; return 10 / z; }    /* 수정 전: 분기를 지워 미탐 */
```

`-fno-builtin`/`-ffreestanding` 에서는 `sqrt` 가 표준 함수라는 보장이 없다. 그런데도
`sqrt(4.0)` 을 2 로 계산해 `r > 3.0` 을 상수로 접었다.

호출에 `nobuiltin` 이 있거나, 호출한 함수에 `"no-builtins"`/`"no-builtin-<이름>"`
속성이 있으면 sqrt·abs 계열 라이브러리 함수를 인식하지 않는다. LLVM 내장 함수
(`llvm.sqrt`, `llvm.abs`)는 그대로 인식한다.

## 2. denormal flush 모드에서 아주 작은 상수와의 비교 (v3.5.11.1)

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp` —
`refine_float_comparison`

```c
double z = 0.0;
if (z >= 1e-310) { printf("%g\n", 3.0 / z); }  /* DAZ: 1e-310 → 0, z == 0 도 통과 */
```

DAZ(`denormal-fp-math=preserve-sign`) 모드에서는 subnormal 상수가 0 으로 읽힌다.
`x >= 1e-310` 은 `x == 0` 에서도 참이다. 그런데 "c > 0 이면 x ≠ 0" 규칙으로 x ≠ 0 을
배운다. x 가 0 으로 알려진 상태라면 그 분기가 도달 불가로 처리될 수 있다.

**재현 여부:** 수정 전(v3.5.19)으로 전역 읽기, 주소를 취한 지역 변수, `-opt=none` 세
형태를 시험했지만 모두 정상적으로 error 가 나왔다. 변수가 형식이 붙은 0 으로 알려진
상태로 이 비교에 들어가는 경우를 만들지 못했으므로, 실제 미탐은 입증되지 않았다.

c 가 0 이 아니라는 점에 기대는 규칙(`>= c>0`, `<= c<0`, `== c≠0`)은 c 가 그 형식의
정규수일 때만 쓴다. half/float/double 은 최소 정규수와 비교한다. long double 은 double 로
읽다가 언더플로한 상수만 제외한다. `>`, `<`, `!=` 규칙은 그대로다.

## 수정 결과

- 1번 반례는 수정 후 error 로 검출된다. 2번 예제는 수정 전후 모두 error 다.
- 일반 빌드(`-fno-builtin` 없음, IEEE 모드)의 sqrt·abs·float 비교 정밀도는 그대로다.
- 기존 예제 회귀 스위트 4종, Juliet Mac 묶음(CWE190 square, CWE369 float, CWE457): 변화 없음.
