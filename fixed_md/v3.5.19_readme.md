# IKOS 3.5.19 — 건전성(soundness) 감사에서 확인된 미탐 수정

## 배경

v3.5.1 ~ v3.5.10.2 의 32개 커밋을 건전성 관점에서 감사했다. 분석기가 실제 실행을
빠짐없이 포함하는지 보는 것이 목적이다. 반례 프로그램을 실제로 분석해 **실제 오류를
놓치거나 도달 가능한 경로를 지우는 것**이 확인된 항목을 수정했다. 각 반례는 원본
IKOS 또는 수정 전 HEAD 와 비교해 재현했다.

---

## 수정 항목

### 1. 같은 폭 `trunc(sext c)` 를 MIN 불가로 오판 (v3.5.8.4 회귀)

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

```c
int c = nd();
if (abs((int)(long)c) <= 4) { return a[c + 4]; }   // c == INT_MIN: abs → INT_MIN 이라 통과
```

`trunc(sext i32 c to i64) to i32` 는 c 그 자체라서 INT_MIN 이 될 수 있다. 그런데도
양쪽 범위 `-4 <= c` 를 넣어 실제 범위 초과를 safe 로 판정했다. sext 원본 폭이
**엄격히 더 좁을 때만** 적용하도록 바꿨다.

### 2. `realloc(NULL, n)` 경로 삭제 (v3.5.1 블록, v3.5.4 로 악화)

**파일:** `numerical.hpp` — `exec_realloc`

내용 복사(`mem_copy`)가 원본 포인터를 non-null 로 단정했다. v3.5.4 의 nullity 복사
관계 때문에 이 단정이 원래 변수에도 전파되어, `p == NULL` 분기가 통째로 사라졌다
(원본 IKOS 는 그 분기의 0 나눗셈을 검출했다). 이제 원본 포인터가 null 일 수 있으면
null 경로(복사 없음)를 따로 계산해 합친다.

### 3. snprintf `"%05s"` 의 `0` 플래그를 너비로 해석 (v3.5.7)

**파일:** `numerical.hpp` — snprintf 정밀 모델

`-` 외 플래그를 처리하지 않아 `0` 이 너비 숫자로 읽혔고, 공백 패딩으로 계산했다.
macOS libc 는 실제로 `'0'` 으로 채운다. `-` 외 플래그(`0 + ' ' # '`)가 있으면 일반
모델을 쓴다.

### 4. scanf 의 크기가 맞지 않는 길이 지정자 (v3.5.9)

**파일:** `numerical.hpp` — `scan_write_size`

`%ld` + `int*`(LP64 에서 8바이트를 씀), `%Lf` + `double*`(x86_64 에서 16바이트),
`%ls` + 16비트 원소를 정밀 크기로 받아, 이웃 필드가 바뀌지 않는다고 판단했다.
모델의 쓰기 크기가 실제 쓰기 크기 이상일 때만 정밀 모델을 쓰도록 했다.
- `%l` 정수: 64비트 대상, 또는 포인터가 32비트인 타깃의 32비트 대상
- `%L` 실수: double 대상 제외
- `%l` 문자열·문자: 32비트 원소만

### 5. `fpext` 가 subnormal 을 정규수로 단정 (v3.5.11.1)

**파일:** `numerical.hpp` — `exec_float_conv`

함수에 `"denormal-fp-math"="preserve-sign"` 같은 non-IEEE 모드가 있으면 subnormal
입력이 0 으로 flush 될 수 있다. 그런데 결과를 무조건 "정규 비영"으로 표시해,
0 나눗셈 검사기가 safe 로 판정했다. 원본이 subnormal 일 수 있으면 결과에도 subnormal
표시를 남긴다. IEEE 모드에서는 여전히 비영으로 판정한다.

### 6. 비교로 배운 "0 아님" 을 힙 객체에 강한 갱신으로 재기록 (v3.5.11.1)

**파일:** `numerical.hpp` — `assume_float_non_zero`

같은 할당 지점(예: 루프 안 malloc)의 여러 객체가 한 메모리 위치로 요약된다. 비교 한
번으로 다른 객체까지 "0 아님"이 되어, `1.0 / *q`(실제 0.0)를 safe 로 판정했다.
지역·전역 객체에만 재기록한다.

### 7. 초기화 증명이 확정 미초기화와 충돌하면 경로 삭제 (v3.5.12)

**파일:** `numerical.hpp` — Load 의 초기화 보강

보강 조건이 "초기화 확정이 아님"이라 확정 미초기화 상태에도 initialized 를 meet 했다.
증명이 틀리면(예: 잘못 붙인 `__attribute__((pure))`) 상태가 ⊥ 가 되어 그 뒤의 무관한
오류까지 사라졌다. 이제 상태가 "모름"일 때만 보강한다.

### 8. 전처리가 상수 null 저장을 `unreachable` 로 바꿈 (기존 결함, v3.5.17 로 노출 확대)

**파일:** `frontend/llvm/src/pass/remove_unreachable_blocks.cpp`

`llvm::removeUnreachableBlocks()` 는 도달 불가 블록 제거 외에, UB 인 명령(상수 null
포인터로의 store 등)을 `unreachable` 로 바꾼다. 그래서 `int *p = 0; *p = 5;` 가 basic 에서
검출되지 않았고, v3.5.17 이 분기를 접으면서 이런 경우가 늘었다. CFG 상 도달 불가인
블록만 지우는 `EliminateUnreachableBlocks()` 로 바꿨다.

### 9. 복사 관계가 힙 할당 위치로 검사 결과를 전파 (v3.5.4, v3.5.5)

**파일:**
- core: `semantic/memory_location.hpp`, `domain/memory/value.hpp`,
  `domain/scalar/abstract_domain.hpp`, `domain/scalar/composite.hpp`,
  `domain/machine_int/{abstract_domain,separate_domain,interval,congruence,interval_congruence,polymorphic_domain}.hpp`
- analyzer: `analysis/memory_location.hpp`

v3.5.4(nullity)와 v3.5.5(정수)는 "메모리 셀 = 읽은 값" 복사 관계를 만든다. 그래서 읽은
값을 비교로 좁히면 셀도 함께 좁혀진다. 그런데 루프 안 malloc 처럼 한 할당 위치가 여러
객체를 대표하면, **쓰기가 전혀 없는데도** 한 객체에 대한 검사가 다른 객체로 전파된다.
원본 IKOS 가 경고하던 실제 오류를 놓쳤다.

```c
for (i = 0; i < 2; i++) { s = malloc(sizeof *s); s->f = unknown(); if (i == 0) first = s; }
int *p = first->f;
if (p != NULL) { int *q = s->f; *q = 1; }   // 원본: warning / 수정 전: 경고 없음
```

메모리 위치 trait `MemoryLocationSummaryTraits::may_be_summary` 를 추가했다(동적 할당
위치 = true). 이런 위치의 셀에서 읽은 정수·포인터는 복사 관계에서 떼어 낸다(값은
유지). 지역·전역 변수의 재로드 개선(v3.5.4/v3.5.5 의 원래 목적)은 그대로다.

### 10. 사용자 정의 malloc/new 를 할당자로 신뢰 (v3.5.14.1)

**파일:** `analyzer/src/analysis/loop_initialization.cpp`

루프 초기화 증명이 이름만 보고 `malloc`/`new[]` 를 새 블록 할당으로 믿었다. 라이브러리
선언일 때만 인정한다.

## 수정하지 않은 항목 (가정 의존, 기록만)

| 항목 | 내용 |
|---|---|
| 할당 시 강한 쓰기 (IKOS 원래 가정) | malloc 의 미초기화 표시, calloc 의 0 기록은 할당 위치에 강한 갱신을 한다. 같은 위치의 이전 객체가 살아 있으면 그 내용도 덮인 것으로 본다. 원본 IKOS 도 int 에서 이렇게 동작해 오류를 놓친다. v3.5.3(float 초기화 상태), v3.5.7(calloc 0)은 같은 규칙을 float·calloc 값으로 넓혔다. 약한 갱신으로 바꾸면 처음 할당한 객체도 "모름"이 되어 힙 미초기화 검출이 사라지므로 바꾸지 않았다. 근본 해결은 recency abstraction 같은 요약 위치 추적이다 |
| 표준 이름 재정의 금지 | `abs`, `sqrt`, C++ `abs` 오버로드, `malloc`/`new` 를 사용자가 다른 의미로 정의하지 않는다고 가정한다 |
| 라이브러리 sqrt 의 faithful rounding | v3.5.8.3 |
| 폐쇄 세계 | 전역은 다른 번역 단위나 asm 이 바꾸지 않는다(v3.5.17, IKOS 의 전역 초기화와 같은 가정) |
| 정상 종료 문자열 | wcslen 은 strlen 과 같이 종료된 문자열을 가정한다 |
| 함수 속성 신뢰 | `readonly`/`readnone` 속성을 믿는다(v3.5.12) |
