# IKOS 3.5.15.1 — (v3.5.15 연장) 내부 루프·exit 출구가 있는 단일 반복 루프

## 문제 요약

v3.5.15 는 정확히 한 번 도는 루프(`for (h = 0; h < 1; h++)`)를 직선 코드로 펴서,
루프 합류 때문에 생기던 오탐을 없앤다. 하지만 다음 두 경우는 변환하지 않았다.

1. 루프 본문에 **다른 루프가 있는 경우** — Juliet `_17` 의 배열 초기화.
   ```c
   for (h = 0; h < 1; h++) {
       for (i = 0; i < 10; i++) { data[i] = i; }   /* 초기화 */
   }
   for (j = 0; j < 1; j++) {
       for (i = 0; i < 10; i++) { printIntLine(data[i]); }
   }
   ```
2. 본문에 **`exit` 로 끝나는 분기가 있는 경우** — `if (data == NULL) {exit(-1);}`.
   LLVM 에서는 이 분기가 루프의 두 번째 출구가 되어 "출구가 헤더 하나"라는 조건에서
   빠졌다.

바깥 루프가 남으면 v3.5.14 의 배열 루프 초기화 증명과 초기화 승격이 "초기화를
건너뛰는 경로(0회 반복)"를 가정하게 된다. 그래서 v3.5.14 이후 CWE457 `_17` good 이
FP 로 남았다. CWE126·CWE415 `_17` 의 malloc 예제도 같은 이유로 정밀도가 떨어졌다.

---

## 수정

**파일:** `frontend/llvm/src/pass/simplify_single_iteration_loops.cpp`

1. 하위 루프 조건을 없앴다. 변환은 헤더만 복제하고 되돌아가는 간선만 바꾼다.
   내부 루프를 포함한 본문 블록은 그대로 한 번 실행되므로 의미가 바뀌지 않는다.
2. 헤더 외의 출구라도, 출구 대상 블록이 `unreachable` 로 끝나고 그 출구의 유일한
   선행 블록이면(`exit()` 같은 반환하지 않는 호출) 허용한다. 실행이 루프로 돌아오지
   않기 때문이다. 이 블록에서 헤더 값을 사용하면 첫 반복 값을 그대로 둔다.
   루프 뒤의 사용만 마지막 검사 값으로 바꾼다.

그 밖의 출구(`break`, `return` 등)는 기존대로 변환하지 않는다.

## 수정 결과 (Mac 하네스)

`_17` 변형 151개(CWE190/191/369/476/690/121/122/124/126/127/415/416/457):

| CWE | 변화 |
|---|---|
| CWE457 | good FP 21 → 0 (배열 18 + `int/double/struct_pointer` 3) |
| CWE126 | good FP 6 제거. bad 6개는 엉뚱한 "use after free" 경고가 정확한 "buffer overflow" 경고로 바뀜 |
| CWE415 | good FP 6 제거. bad 6개는 `possible double free`(warning)가 `double free`(error)로 바뀜 |
| 그 외 | 변화 없음 |

- 새로 생긴 경고 없음. bad 는 위 두 CWE 에서 더 정확해졌고, 미탐은 없다.
- CWE457 전체(C 파일 560개): bad 변화 없음, good FP 프로그램 76 → 55
  (`_12`, `_63`, `_64` 만 남음).
- 값 보존 확인: 내부 루프와 `exit` 출구가 있는 한 번 도는 루프에서 `exit` 블록 안의
  `h == 0`, 루프 뒤의 `h == 1` 이 증명되고, 틀린 assert 는 error 로 잡힌다.
- 기존 예제 회귀 스위트: 위 CWE415·CWE457 `_17` 개선 외 변화 없음.
