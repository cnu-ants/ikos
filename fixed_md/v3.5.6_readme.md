# IKOS 3.5.103 — wcslen 모델 추가로 basic의 버퍼 오버플로 오탐 수정

## 문제 요약

정상적으로 NULL 종료된 `wchar_t` 배열의 길이를 `wcslen()`으로 구해 반복문에
사용하면, `--opt=basic`에서도 가능한 버퍼 오버플로 경고가 발생했다.

```c
#include <stddef.h>
#include <wchar.h>

static void test(void) {
  wchar_t data[4] = L"abc", dest[4] = L"xyz";
  size_t length = wcslen(dest);
  for (size_t i = 0; i < length; ++i) {
    dest[i] = data[i];  // 수정 전: possible buffer overflow
  }
}

int main(void) {
  test();
  return 0;
}
```

실제 `length`는 3이고, 반복문은 인덱스 0·1·2만 접근하므로 두 배열의 범위 안이다.
이번 수정은 `wcslen()` 모델을 추가하여 위 예제의 `basic` 오탐을 해소한다.
`none`에서 발생하는 부호 변환 재로드 문제는 이번 수정 범위에 포함하지 않았다.

## 근본 원인

### 원인 1 — wcslen을 알려진 라이브러리 함수로 인식하지 않음

**파일:** `frontend/llvm/src/import/library_function.cpp`

**관련 파일:** `ar/include/ikos/ar/semantic/intrinsic.hpp`,
`ar/src/semantic/intrinsic.cpp`

기존에는 `strlen()`을 `ar::Intrinsic::LibcStrlen`으로 변환했지만,
`wcslen()`의 등록과 AR intrinsic 정의는 없었다.
따라서 `wcslen()`은 일반 외부 함수 호출로 남았다.

```text
수정 전: call @wcslen(...)
수정 후: call @ar.libc.wcslen.si32(...)  // 32비트 wchar_t인 경우
```

`strlen()`은 바이트 단위 문자열을 처리한다. `wcslen()`은 `wchar_t` 원소의 개수를
반환하므로, 함수 이름만 `strlen()`에 연결하면 올바른 길이 상한을 구할 수 없다.
재현 환경에서는 `wchar_t`가 4바이트라 배열의 저장 크기는 16바이트이지만,
문자열 길이의 상한은 15가 아닌 3이어야 한다.

### 원인 2 — 일반 외부 호출 처리로 길이와 입력 메모리 정보 유실

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `exec_unknown_extern_call()`, `exec_unknown_call()`

일반 외부 함수는 포인터 인수가 가리키는 메모리를 변경할 수 있다고 처리하고,
반환값은 초기화된 임의의 값으로 만든다.

이 경로 때문에 `wcslen(dest)`의 반환값에 유효한 길이 상한이 반영되지 않았고,
읽기 전용 입력인 `dest`의 내용도 메모리 무효화 대상이 됐다.
분석기는 `i < length`에서 작은 인덱스 범위를 얻지 못해 `data[i]` 읽기와
`dest[i]` 쓰기 모두에서 가능한 범위 초과를 진단했다.

### none에 함께 남아 있는 별도 문제

원인을 구분하기 위해 수정 전 분석기에서 다음 비교를 수행했다.

| 사례 | basic | none |
|------|:-----:|:----:|
| 원래 `wcslen(dest)` 예제 | warning | warning |
| `length`를 상수 `3`으로 지정 | safe | warning |
| `char` 배열과 `strlen()` 사용 | safe | warning |

`none`에서는 조건에 사용한 unsigned 인덱스를 배열 접근에서 signed 형태로
다시 읽는 AR이 남았다. 이 변환을 거친 재로드에 조건의 범위가 전달되지 않았다.
3.5.102의 정수 복사 관계 보완은 같은 비트 폭·부호의 단순 복사를 다뤘으며,
이 부호 변환 경로까지 해결한 것은 아니다.

따라서 이번에는 사용자의 요청에 따라 `basic`의 라이브러리 모델 누락만 수정했다.
최적화 옵션에 따라 모델을 켜고 끄는 방식은 사용하지 않았다.
추가한 모델은 공통으로 동작하지만, `none`의 별도 재로드 경고는 남는다.

## 수정 내용

### 수정 1 — wchar_t 폭을 반영한 AR intrinsic과 함수 인식 추가

**파일:** `ar/include/ikos/ar/semantic/intrinsic.hpp`

**파일:** `ar/src/semantic/intrinsic.cpp`

`LibcWcslen`을 추가하고, 원소 타입을 타입 매개변수로 받도록 정의했다.
반환 타입은 unsigned `size_t`, 인수는 해당 원소 타입의 포인터이다.

```text
32비트 원소: ui64 @ar.libc.wcslen.si32(si32*)
16비트 원소: ui64 @ar.libc.wcslen.si16(si16*)
```

위 반환 폭은 검증한 64비트 대상의 예시이며, 실제 반환 타입은 대상의 `size_t`를 따른다.

**파일:** `frontend/llvm/src/import/library_function.hpp`

**파일:** `frontend/llvm/src/import/library_function.cpp`

**파일:** `frontend/llvm/src/import/bundle.cpp`

라이브러리 함수 검색에 LLVM 함수 타입도 전달하여, `wcslen()`의 포인터 원소에서
16비트 또는 32비트 폭을 확인하고 해당 intrinsic을 생성한다.
기존 외부 함수 시그니처 일치 검사도 유지한다.

원소 폭을 알 수 없는 opaque pointer나 지원하지 않는 원소 타입은 추측하여
모델링하지 않고, 기존 일반 함수 처리 경로에 남긴다.

### 수정 2 — 읽기 전용 wcslen 실행 모델 추가

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `exec_wcslen()`

입력 포인터의 접근을 준비한 뒤 반환값을 초기화된 임의의 정수로 만들고,
가능한 메모리 대상별로 길이 상한을 제한한다. 입력 메모리는 변경하거나 잊지 않는다.

상한 계산에는 객체 크기의 상한, 포인터 바이트 오프셋의 하한,
대상 데이터 레이아웃의 원소 크기를 사용한다.

```text
남은 바이트 수의 상한 = 객체 크기의 상한 - 포인터 오프셋의 하한
길이 상한 = floor(남은 바이트 수의 상한 / sizeof(wchar_t)) - 1
```

마지막 `-1`은 종료 문자 한 원소의 공간을 제외하는 것이다.
기존 `strlen()` 모델처럼 정상 종료된 문자열에 대한 호출을 가정한 상한이다.

실제 추가 코드의 핵심은 다음과 같다.

```cpp
auto remaining = size.ub().to_z_number() - offset.lb().to_z_number();
if (remaining < element_size) {
  tmp.set_normal_flow_to_bottom();
} else {
  auto max_length = remaining / element_size - 1;
  tmp.normal().int_add(IntPredicate::LE,
                       lhs.var(),
                       MachineInt(max_length,
                                  result_ty->bit_width(),
                                  result_ty->sign()));
}
```

- 빼기와 나눗셈은 수학적 정수로 계산하여 `size_t`의 언더플로·랩어라운드를 피한다.
- 전역 객체는 타입의 저장 크기를 사용하고, 그 외에는 추적된 할당 크기를 사용한다.
- 배열 중간을 가리키면 그 오프셋을 제외한 나머지 공간만 계산한다.
- 여러 대상을 가리키면 각 대상의 결과를 합류한다. 대상 정보가 TOP이면
  정밀한 객체별 상한을 적용하지 않는다.
- 종료 문자 한 개조차 들어갈 수 없는 대상은 정상 반환 경로에서 제외한다.
  호출 시점의 메모리 접근 검사는 실행 모델 적용 전에 수행된다.

원래 예제는 남은 크기가 16바이트, 원소 크기가 4바이트이므로
`length`가 `[0, 3]`으로 제한된다. 따라서 `basic`의 반복문 본문에서
인덱스를 `[0, 2]`로 제한할 수 있다.

이 모델은 실제 문자들을 순회하여 길이를 정확히 3으로 계산하는 구현은 아니다.
유효한 상한만으로 이번 배열 접근의 안전성을 증명한다.

### 수정 3 — 관련 분석과 검사기에 새 intrinsic 연결

**파일:** `analyzer/include/ikos/analyzer/analysis/pointer/constraint.hpp`

**파일:** `analyzer/src/checker/buffer_overflow.cpp`

**파일:** `analyzer/src/checker/null_dereference.cpp`

**파일:** `analyzer/src/checker/soundness.cpp`

**파일:** `analyzer/src/checker/memory_watch.cpp`

- 포인터 분석에는 반환 포인터나 입력 변경이 없는 정수 반환 함수로 연결한다.
- NULL 검사기는 입력 포인터의 NULL 여부를 검사한다.
- BOA는 첫 번째 `wchar_t` 한 원소가 접근 가능한지 검사한다.
  바이트 문자열의 첫 1바이트 검사와 달리 실제 원소의 저장 크기를 사용한다.
- soundness와 memory watch에는 알려진 읽기 전용 함수로 연결하여,
  알 수 없는 쓰기 호출로 처리하지 않도록 한다.

변경한 분석기 소스는 총 11개이며, 정수 부호 변환이나 재로드 도메인은 변경하지 않았다.

## 수정 결과

| 사례 | 수정 전 | 수정 후 |
|------|:-------:|:-------:|
| 원래 C 예제, `basic` | 배열 읽기·쓰기 warning | **경고 없음** |
| 원래 예제를 C++17로 분석, `basic` | 전용 모델 없음 | **경고 없음** |
| 원래 C 예제, `none` | warning | **재로드 경고 남음** |
| NULL 인수의 `wcslen()` | 일반 외부 함수 처리 | **NULL·BOA error 확인** |
| 배열 끝 다음 원소에서 `wcslen()` 호출 | 일반 외부 함수 처리 | **BOA error 확인** |
| 복사 대상 또는 원본 배열이 부족한 경우 | 가능한 범위 초과 | **진단 유지** |

### 검증 결과

- 원래 예제를 C와 C++17로 각각 분석하여 `basic`에서 경고·오류가 없음을 확인했다.
- 16·32비트 `wchar_t` 각각에서 안전 사례 6개는 진단이 없고,
  위험 사례 6개는 진단되는 것을 확인했다.
  전역 배열, 중간 원소 포인터, 동적 할당, 빈 문자열, 입력 내용 보존,
  작은 원본·대상 배열, NULL 및 범위 밖 포인터를 포함했다.
- 16비트 검증은 `-fshort-wchar`와 폭에 맞는 별도 함수 선언을 사용해
  컴파일·정적 분석만 수행했다. 대상 시스템 libc에 호출을 실행한 검증은 아니다.
- 크기가 다른 두 배열 중 하나를 가리키는 안전 사례 1개는 양쪽 폭에서 오탐이 남았다.
  포인터 대상과 반환 길이 사이의 상관관계를 합류 후 유지하지 못하는 한계로 기록했다.
- 기존·관련 검사 구성 **228개 통과**:
  BOA 128개, 메모리 52개, NULL 14개, signed/unsigned overflow 9개,
  이전 부동소수점 미초기화 관련 구성 25개.
- 앞선 검증에서 수정 전에도 실행 오류가 확인된 BOA의 `test-51.c`,
  `test-51-unsafe.c`, `test-56.cpp`는 이번 BOA 실행에서 제외했으며,
  위 통과 개수에 포함하지 않았다.
- 빌드와 `git diff --check`를 통과했다.

프로젝트에 새 회귀 테스트 파일을 추가하거나 기존 테스트를 수정하지 않았다.
검증용 추가 코드와 결과는 프로젝트 밖의 임시 디렉터리에서 사용했다.

## 적용 범위와 한계

이번 수정은 `wcslen()`의 길이 상한과 읽기 전용 의미를 추가하여,
제시된 예제의 `basic` 오탐을 해결한 것이다.

- **none의 부호 변환 재로드:** 별도 미해결 문제로 남긴다.
- **정확한 길이:** 객체 크기에 근거한 상한을 계산하며, 문자열 내용을 읽어
  첫 종료 문자의 위치를 찾지는 않는다. 큰 배열 안에 짧은 문자열이 있으면
  실제 길이보다 큰 상한이 남을 수 있다.
- **NULL 종료 검증:** 기존 `strlen()`과 같이 정상 종료된 문자열을 가정한다.
  BOA가 확인하는 것은 첫 원소의 접근 가능성이다. 종료 문자가 없는 배열에서
  `wcslen()`이 끝까지 읽는 범위의 안전성을 완전히 검사한 것은 아니다.
- **복수 대상과 크기 정보:** 대상별 포인터·길이의 상관관계나 정밀한 할당 크기를
  유지하지 못하면 오탐이 남을 수 있다.
- **원소 타입:** LLVM 포인터에서 16·32비트 원소 폭을 확인하는 경우를 지원한다.
  폭을 알 수 없는 경우에는 기존 일반 함수 처리 경로를 사용한다.

따라서 이번 변경을 wide 문자열 관련 분석 전체의 완전한 지원으로 해석하지 않는다.
