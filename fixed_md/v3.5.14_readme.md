# IKOS 3.5.111 — 범위 인덱스 읽기의 미초기화 미탐 및 루프 초기화 오탐 수정

## 문제 요약

배열의 일부만 초기화한 뒤 범위 인덱스로 읽을 때, 초기화된 원소와
미초기화된 원소가 섞여 있어도 `uva` 검사가 safe로 판정하는 문제가 있었다.

```c
#include <stdio.h>

typedef struct {
  int intOne;
  int intTwo;
} Pair;

void test(void) {
  Pair data[10];
  for (int i = 0; i < 5; ++i) {
    data[i].intOne = i;
    data[i].intTwo = i;
  }
  for (int i = 0; i < 10; ++i)
    printf("%d\n", data[i].intOne); // 기대: warning
}

int main(void) {
  test();
  return 0;
}
```

`data[5]`부터 `data[9]`까지는 초기화되지 않았다. 하지만 수정 전에는
`--opt=basic`과 `--opt=none` 모두 미초기화 진단이 없었다.
수정 후에는 두 설정 모두 출력 위치에 warning이 발생한다.
읽기 인덱스가 범위로 합쳐지므로, 이 예제의 결과는 error가 아닌 warning이다.

첫 수정으로 미탐을 제거한 뒤에는, 루프로 모든 원소를 초기화한 안전한
벤치마크 G03·G09·G10에서 오탐이 드러났다. 이번 변경에는 해당 루프의
초기화를 별도로 증명하여 이 세 오탐을 제거한 후속 수정도 포함한다.

기존 `uva` checker를 사용한다. 새 검사기나 활성화 옵션은 추가하지 않았다.

## 근본 원인

### 원인 1 — 범위 주소에서 읽은 임의의 값을 초기화된 값으로 처리

**파일:** `core/include/ikos/core/domain/memory/value.hpp`  
**함수:** `ValueDomain::mem_read()`

메모리 오프셋이 하나로 확정된 경우에는 해당 셀의 초기화 상태를 읽는다.
반면 오프셋이 범위인 경우에는 다음 연산으로 읽기 결과를 만들었다.

```cpp
this->_scalar.scalar_assign_nondet(lhs.var());
```

이 연산은 수치 값을 임의의 값으로 만들면서 **초기화 상태를 initialized로
설정**한다. 수치 값을 모른다는 사실과 초기화 여부를 모른다는 사실은 다르다.
기존 구현은 두 정보를 구분하지 않아, 미초기화 원소를 읽을 가능성이 있어도
결과를 초기화된 것으로 바꿨다.

구조체 배열에만 한정된 문제는 아니다. 알려진 메모리 객체를 범위 오프셋으로
읽는 공통 경로의 문제이므로 정수·부동소수점·문자 배열 등에도 영향을 준다.

### 원인 2 — 루프의 범위 저장과 상태 합류에서 초기화 셀 정보 손실

원인 1을 고치면 메모리 정보가 부족한 읽기는 warning이 된다. 이때 다음처럼
실제로는 모든 원소를 초기화한 코드에서도 경고가 나타났다.

```c
int a[4];
for (int k = 0; k < 4; ++k)
  a[k] = k;
printf("%d\n", a[i]); // 0 <= i < 4이면 안전
```

루프 분석 중에는 인덱스가 범위로 확대되고 메모리 상태가 합류한다.
그 과정에서 원소별 셀 정보가 사라질 수 있다. 기존 메모리 도메인에는
루프 종료 후 모든 해당 바이트에 저장했다는 사실이 남지 않는다.

따라서 첫 수정 뒤의 경고는 새 검사기가 생긴 결과가 아니라, 기존의
초기화 정밀도 손실이 드러난 결과다. 경고를 일괄 억제하지 않고,
제한된 형태의 루프에 대해 초기화가 보장됨을 증명하도록 보완했다.

## 수정 내용

### 수정 1 — 범위 읽기의 초기화 상태를 메모리에서 별도로 계산

**파일:** `core/include/ikos/core/domain/memory/value.hpp`  
**추가 함수:** `range_read_uninitialized()`

오프셋이 여러 값일 때도 수치 정보와 초기화 정보를 분리한다.

```cpp
auto offset = this->_scalar.pointer_offset_to_interval_congruence(ptr);
Uninitialized state = Uninitialized::bottom();
for (MemoryLocationRef addr : addrs) {
  state.join_with(this->range_read_uninitialized(addr, offset, size));
  if (state.is_top()) {
    break;
  }
}
this->_scalar.scalar_forget(lhs.var());
this->_scalar.uninit_refine(lhs.var(), state);
```

가능한 주소와 읽기 위치의 초기화 상태를 join으로 합친다.

| 확인된 상태 | 읽기 결과의 초기화 상태 | uva 판정 |
|---|---|---|
| 모든 후보가 초기화됨 | initialized | safe |
| 모든 후보가 미초기화됨 | uninitialized | error |
| 초기화·미초기화가 섞이거나 정보가 부족함 | TOP — 초기화 여부 불확실 | warning |

수치 값은 계속 임의의 값으로 처리한다. 초기화 상태만 메모리에서 전달한다.
먼저 `scalar_forget()`을 수행하므로 이전 결과 변수의 initialized 상태가 남지
않는다. initialized로 대입한 뒤 refine하는 방식은 사용하지 않는다.

`range_read_uninitialized()`는 다음 순서로 검사한다.

1. 읽기 후보 전체 바이트 범위를 계산하고 겹치는 메모리 셀을 정렬한다.
2. 같은 초기화 상태의 여러 셀이 전체 범위를 빈틈없이 덮으면 그 상태를 반환한다.
3. 전체 범위로 증명할 수 없으면 interval-congruence의 간격을 사용해
   후보 오프셋별 기존 읽기 검사를 수행하고 결과를 합친다.
4. 셀이 없거나 계산을 끝낼 수 없으면 initialized를 가정하지 않고 TOP을 반환한다.

비용 제한을 위해 후보 열거는 최대 128개, 이때 사용하는 읽기 바이트 마스크는
최대 4,096바이트로 제한한다. **전체 바이트 범위가 덮인다는 증명은 이 제한보다
먼저 수행**하므로 큰 배열을 무조건 포기하는 것은 아니다.
주소 범위 계산에서 오버플로가 발생해도 TOP으로 처리한다.

오프셋이 하나인 기존 읽기 경로는 유지한다. 대상 객체 자체를 알 수 없는
포인터의 별도 처리까지 이번 수정으로 해결했다고 보지는 않는다.

### 수정 2 — 완료된 카운터 루프의 초기화 범위를 증명

**새 파일:** `analyzer/src/analysis/loop_initialization.cpp`  
**클래스:** `LoopInitializationProof`  
**진입 함수:** `prove_loop_initialized_load()`

일반 메모리 읽기로 초기화를 확인하지 못하면, 연결된 LLVM 명령에서
초기화 루프와 저장 범위를 검사한다. LLVM 코드는 변경하지 않는다.

주요 증명 조건은 다음과 같다.

- 같은 함수의 고정 크기 스택 객체이며, 주소가 외부로 노출되지 않아야 한다.
  대상 포인터를 함수에 전달하거나 지원하지 않는 별칭이 생기면 증명을 중단한다.
- 카운터가 0에서 시작하고 1씩 증가하며, 조건이 양의 상수 `N`에 대한
  `k < N`인 루프만 지원한다. `basic`의 SSA 카운터와 `none`의 메모리 카운터를
  각각 확인한다.
- 루프 헤더와 종료 블록이 읽기 위치를 지배해야 한다. 즉 루프를 우회하여
  읽기로 가는 경로가 없어야 하며, 읽기는 초기화 루프 밖에 있어야 한다.
- 저장이 매 반복의 되돌아가는 경로에서 실행되어야 한다. 카운터가 메모리에
  남는 경우에는 저장이 카운터 갱신보다 앞서는지도 검사한다.
- 저장 값은 상수, 검증된 카운터, 이들로부터 계산된 값 등 초기화가 확인되는
  값이어야 한다. 객체에 대한 다른 저장도 미초기화 값을 도입하지 않아야 한다.
- GEP의 상수 오프셋과 카운터 간격으로 쓰기 범위를 계산한다. 정수 계산의
  오버플로, 인덱스 부호 확장, 할당 객체의 경계를 검사한다.
- 모든 반복의 쓰기 바이트 범위를 합친 뒤, 가능한 읽기의 모든 바이트가
  그 범위에 포함되는 경우에만 초기화됐다고 인정한다.

따라서 일부 원소만 초기화한 루프를 전체 초기화로 취급하지 않는다.
저장이 생략되는 분기, 조기 종료, 루프 우회, 미초기화 값의 덮어쓰기 등도
전체 초기화의 근거로 사용하지 않는다.

분석 비용은 객체 크기 1 MiB, 반복 횟수 4,096회, 증명 작업 예산 32,768회로
제한한다. 전체 읽기 범위를 한 번에 덮는지 확인한 뒤 필요한 후보 열거도
최대 4,096개로 제한한다. 지원 조건이나 예산을 만족하지 못하면 증명 실패로
돌아가며, 기존 경고를 임의로 제거하지 않는다.

이 증명은 **초기화 상태만 보완**한다. 배열 원소의 정수 값, 부동소수점 값,
포인터의 null 여부까지 새로 추론하는 기능은 아니다.

### 수정 3 — 기존 load 처리 및 빌드에 연결

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

비휘발성 스칼라 load에서 `mem_read()`를 수행한 뒤 초기화가 확인되지 않으면,
기존 `prove_initialized_load()`와 새 `prove_loop_initialized_load()`를 검사한다.
증명에 성공한 경우에만 읽기 결과의 초기화 상태를 보완한다.
기존 미초기화 증명 경로도 유지한다.

**파일:** `analyzer/include/ikos/analyzer/analysis/initialization.hpp`  
**파일:** `analyzer/CMakeLists.txt`

새 함수 선언과 소스 파일 빌드 등록을 추가했다.
프로젝트에 새 회귀 테스트 파일이나 실행 스크립트는 추가하지 않았다.

## 수정 결과

사용자 벤치마크 `bench/mixed_range_uninit_bench.c`를 확인했다.
아래 기본 설정 결과는 interval 도메인과 기본 전역 초기화 정책을 사용한 것으로,
**basic과 none에서 동일하다.**

| 사례 | 범위 읽기 수정 후, 루프 증명 추가 전 | 최종 결과 — 기본 설정 |
|---|---|---|
| K01·K03 | error | error 유지 |
| K02·K04 | 경고 없음 | 경고 없음 유지 |
| B01~B15 | 15개 모두 warning | 15개 모두 warning 유지 |
| G03 — int 배열 전체 루프 초기화 | warning | **경고 없음** |
| G09 — 구조체 배열 필드 루프 초기화 | warning | **경고 없음** |
| G10 — double 배열 루프 초기화 | warning | **경고 없음** |
| 나머지 G 사례, G07 제외 | 경고 없음 | 경고 없음 유지 |
| G07 — 간격 인덱스 | warning | warning — 도메인 설정으로 제거 가능 |
| C01·C02 | warning | warning — 남은 정밀도 한계 |
| C03의 지역 배열 `a[i]` | warning | **경고 없음** |
| C03의 정적 배열 `big[i]` | warning | warning — 전역 초기화 설정으로 제거 가능 |

최초 원본 Pair 예제는 범위 읽기 수정 전 basic/none 모두 safe였으며,
최종 버전에서는 두 설정 모두 warning이다.
안전한 G03·G09·G10을 보완한 뒤에도 B 그룹의 미초기화 경고는 모두 유지됐다.

### G07 — 인덱스 간격을 잃는 문제

G07은 `a[0]`, `a[2]`를 초기화하고 `j`가 0 또는 1일 때 `a[2*j]`를 읽는다.
기본 interval 도메인은 중간의 미초기화 위치까지 포함할 수 있어 경고한다.
`-d=interval-congruence`를 사용하면 이 벤치마크에서는 간격을 보존하여
경고가 사라진다. 기본 도메인을 자동으로 바꾸지는 않았다.

### C03 — 지역 배열과 큰 전역 배열의 원인이 다름

```c
static int big[1000]; // C 언어 규칙상 전부 0으로 초기화
int a[1000];
for (int k = 0; k < 500; ++k)
  a[k] = k;
// 0 <= i < 500
printf("%d %d\n", a[i], big[i]);
```

두 읽기 모두 실제로 안전하다. 새 루프 증명으로 `a[i]` 경고는 제거됐다.
남은 `big[i]` 경고는 기본 `--globals-init=skip-big-arrays` 정책이 큰 전역 배열의
초기화를 생략하기 때문이다. `--globals-init=all`로 분석하면 사라진다.
지역 배열 경고가 후보 열거 개수 제한 때문에 남아 있는 상태는 아니다.

| 설정 — basic/none 공통 | G 그룹 11개 | C03 | C01·C02 | B 그룹 15개 |
|---|---|---|---|---|
| 기본 설정 | G07만 warning | `big[i]`만 warning | warning | 모두 warning |
| `--globals-init=all` | G07만 warning | 경고 없음 | warning | 모두 warning |
| 위 옵션 + `-d=interval-congruence` | **모두 경고 없음** | 경고 없음 | warning | 모두 warning |

## 검증 및 남은 한계

다음 검증을 수행했다. 새 검증 코드는 임시 디렉터리에서 사용했으며
프로젝트에는 추가하지 않았다.

- 범위 읽기 수정 단계: 4개 원소의 초기화 조합 16개 × int/double × basic/none,
  **64개 분석 결과가 기대와 일치**했다.
- 최종 루프 증명: 안전한 사례와 부분 초기화·분기·break·continue·주소 노출·
  미초기화 덮어쓰기 등의 C 사례 35개 × basic/none, **70개 모두 기대와 일치**했다.
- 직접 작성한 LLVM IR 5개 × basic/none, **10개 모두 기대와 일치**했다.
  루프 우회와 인덱스 부호 확장 때문에 잘못 초기화됐다고 판단하지 않는지 확인했다.
- 사용자 벤치마크를 basic/none 각각 기본 설정, 전역 전체 초기화,
  전역 전체 초기화 + interval-congruence의 **6가지 구성**으로 확인했다.
- 기존 memory·dbz·null·sio·uio·dfa 테스트 그룹 **6개 모두 통과**했다.
- 실행 가능한 기존 UVA 검사 33개 중 **32개 통과**했다. 나머지
  `test-2-error-2.c`는 테스트가 error를 기대하지만 현재 결과는 warning인
  기존 기대값 불일치가 남아 있다. 기존 LLVM importer 오류로 실행할 수 없는
  C++ 사례 4개는 제외했다. UVA 전체가 통과했다고 보지는 않는다.

C01의 동적 길이 `n`과 `i < n`의 관계, C02의 `i % 2 == 0` 조건을 역으로
전파하는 처리는 이번 범위 밖이다. 위 정밀도 옵션을 함께 사용해도 두 경고는
남는다. 힙 배열의 일반적인 루프 초기화, 외부로 노출된 객체, 임의의 중첩 루프,
비정형 카운터까지 모두 해결한 배열 요약 도메인은 아니다.

## 빌드 및 재확인

수정 소스를 별도 임시 빌드로 검증했다. 기존에 설치한 `ikos-fixed2`에
반영하려면 사용 중인 ikos2 빌드를 다시 설치해야 한다.

```sh
/Applications/CLion.app/Contents/bin/ninja/mac/aarch64/ninja \
  -C /Users/baesungmin/Projects/ants/ikos2/cmake-build-debug -j4 install
```

기본 설정 비교:

```sh
ikos-fixed2 -a=uva --opt=basic -o /private/tmp/mixed-range-basic.db \
  /Users/baesungmin/Projects/ants/ikos2/bench/mixed_range_uninit_bench.c

ikos-fixed2 -a=uva --opt=none -o /private/tmp/mixed-range-none.db \
  /Users/baesungmin/Projects/ants/ikos2/bench/mixed_range_uninit_bench.c
```

G07과 C03의 설정 영향을 함께 확인:

```sh
ikos-fixed2 -a=uva --opt=basic \
  -d=interval-congruence --globals-init=all \
  -o /private/tmp/mixed-range-precise-basic.db \
  /Users/baesungmin/Projects/ants/ikos2/bench/mixed_range_uninit_bench.c

ikos-fixed2 -a=uva --opt=none \
  -d=interval-congruence --globals-init=all \
  -o /private/tmp/mixed-range-precise-none.db \
  /Users/baesungmin/Projects/ants/ikos2/bench/mixed_range_uninit_bench.c
```

이 벤치마크는 `argc`로 사례를 선택하므로 전체 사례를 확인할 때 `--argc`로
값을 고정하지 않는다. 안전한 G 그룹의 경고가 모두 사라져도 K01·K03과
B 그룹, C01·C02의 진단은 남는 것이 확인된 결과다.
