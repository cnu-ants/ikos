# IKOS 3.5.8.2 — (v3.5.8 연장) MIN 제외 검사 없는 절댓값 조건의 상한 전달

## 문제 요약

v3.5.8/v3.5.8.1 은 `abs(x) <= M` 형태의 검사를 보면 참 쪽에 `-M <= x <= M` 를 추가한다.
단, `abs(MIN)` 은 표현할 수 없으므로 `x != MIN` 같은 검사가 앞에 없으면 아무것도
추가하지 않았다.

Juliet `int64_t` square 의 good 은 MIN 제외 검사 없이 다음처럼 쓴다.

```c
void goodB2GSink(int64_t data)          /* data = LLONG_MAX 가 전달됨 */
{
    if (imaxabs((intmax_t)data) <= sqrtl(LLONG_MAX)) {
        int64_t result = data * data;   /* error: signed integer overflow (data = 9223372036854775807) */
        printLongLongLine(result);
    } else {
        printLine("data value is too large to perform arithmetic safely.");
    }
}
```

`data` 가 같은 함수 안의 상수면 비교 자체가 상수로 증명돼 문제가 없다. 하지만 인자나
전역, 다른 함수를 거쳐 오면(`_21`~`_68`) 조건에서 아무것도 얻지 못한다. 그러면
실제로 갈 수 없는 참 쪽에서 `data = LLONG_MAX` 로 곱셈을 분석해 **error** 를 보고한다.

---

## 근본 원인

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp` — `guard()`

MIN 이 제외되지 않으면 조건 전체를 포기했다. 그런데 `abs(MIN)` 은 실제로 `MIN` 이 되고,
`MIN <= M` 이라 조건을 통과한다. 따라서 **상한 `x <= M` 은 MIN 을 포함해도 항상
성립**한다. 하한 `x >= -M` 만 MIN 때문에 성립하지 않는다.

---

## 수정

MIN 제외 검사가 없을 때는 참 쪽에 **상한만** 추가한다(하한 자리에는 항상 참인
`x >= MIN` 을 넣는다). 원래 조건과 호출은 그대로 둔다.

- `abs` 결과를 sext 로 넓힌 비교: `sext(abs(MIN))` 은 음수라 통과하지만 `MIN <= M` 이다.
- zext 로 넓힌 비교: `zext(abs(MIN)) = 2^(w-1)` 은 x 폭에 들어가는 어떤 M 보다 크므로
  통과하지 못한다.

MIN 이 그대로 남으므로, 실제로 MIN 이 들어올 수 있는 fscanf/rand good 의
`data * data` 경고(정당한 경고)는 유지된다.

## 수정 결과 (Mac 하네스, CWE190 int/int64_t/char/short square)

- `int64_t_max_square` good FP 20개 해소: `_21`, `_22`, `_34`, `_41`~`_45`,
  `_51`~`_54`, `_61`~`_68`. `_72`~`_74`(STL) 는 남는다.
- `_12` bad: bad 함수 안 검사한 쪽 분기의 경고만 사라지고, 검사 없는 쪽 TP 는 유지된다.
- `int64_t` fscanf/rand good: 경고 유지(정당). 메시지에 `data <= 3037000499` 가 붙는다.
- int/char/short square 판정 변화 없음.
- 기존 예제 회귀 스위트: 판정 변화 없음(int64 square 예제 2개 메시지에 범위 추가).
