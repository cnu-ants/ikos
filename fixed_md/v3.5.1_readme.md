# IKOS 3.5.1 — Nullity Checker Fix

## 문제 요약

IKOS 3.5의 Nullity Checker(null 역참조 분석)에서 `malloc`, `realloc` 계열 함수가
실패 시 `NULL`을 반환할 수 있음에도 분석기가 이를 무시하고 항상 non-null로 처리하는
버그가 존재했다.

```c
int *p = (int *)malloc(sizeof(int));
*p = 5;   // 실제로는 unsafe — 그러나 분석 결과는 "safe"  ← 버그
```

반면 `calloc`은 동일한 상황에서 올바르게 경고를 출력하고 있었다.

```c
int *p = (int *)calloc(1, sizeof(int));
*p = 5;   // warning: pointer 'p' might be null  ← 정상 동작
```

---

## 근본 원인

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

### 원인 1 — `allocate_memory(MachineInt alloc_size)`

`malloc(sizeof(int))`처럼 크기가 컴파일 타임 상수인 경우, 엔진은 할당된 메모리를
미초기화 상태로 표시하기 위해 `mem_write(ptr, undefined, alloc_size)`를 호출한다.

`mem_write` 내부에서는 사용자 역참조를 모델링하기 위해
`nullity_assert_non_null(ptr)`을 호출하는데, 이 과정에서 포인터의 nullity가
`top()`(null 가능)에서 `non_null`로 **좁혀진다**.

이때 `calloc`은 크기 인자를 별도로 처리하여 `mem_write`를 거치지 않으므로
nullity가 `top()`으로 유지되었고, 그 결과 두 함수의 동작이 달라졌다.

### 원인 2 — `exec_realloc` 내 `mem_copy`

`realloc` 처리 시 기존 메모리 내용을 복사하기 위해 호출하는
`mem_copy(lhs.var(), ptr.var(), size)` 역시 내부에서
`nullity_assert_non_null(dest)`를 호출하여 결과 포인터를 `non_null`로 좁혔다.

## 수정 내용

### 수정 1 — `allocate_memory(MachineInt alloc_size)` (line ~264)

```cpp
this->_inv.normal().mem_write(ptr, ScalarLit::undefined(), alloc_size);
// 추가: mem_write가 내부에서 nullity_assert_non_null을 호출해
// Nullity::top()을 non_null로 좁히므로, 원래 nullity를 복원한다.
this->_inv.normal().nullity_set(ptr, nullity);
```

`mem_write`는 사용자 코드의 역참조가 아닌 메모리 모델 초기화 목적으로 호출되는
것이므로 nullity를 좁혀서는 안 된다. `mem_write` 직후 호출자가 지정한 `nullity`
값으로 복원한다.

### 수정 2 — `exec_realloc` 내 `mem_copy` (line ~2896)

```cpp
this->_inv.normal().mem_copy(lhs.var(), ptr.var(), size);
// 추가: mem_copy가 dest의 nullity를 non_null로 좁히므로 복원한다.
// realloc은 실패 시 NULL을 반환하므로 top()이 올바른 상태다.
if (!this->_inv.is_normal_flow_bottom()) {
    this->_inv.normal().nullity_set(lhs.var(), Nullity::top());
}
```

## 수정 결과

| 함수 | 3.5 (수정 전) | 3.5.1 (수정 후) |
|------|:---:|:---:|
| `malloc` | safe (버그) | **warning** |
| `calloc` | warning | warning |
| `realloc(NULL, n)` | safe (버그) | **warning** |
| `realloc(p, n)` | safe (버그) | **warning** |
| `aligned_alloc` | warning | warning |
| `strdup` | warning | warning |

null 체크 후 역참조하는 경우는 기존과 동일하게 safe로 판정된다.

```c
int *p = (int *)malloc(sizeof(int));
if (p != NULL) {
    *p = 5;   // safe — null 체크 완료
}
```
