# IKOS 3.5.8.3 — (v3.5.8 연장) Linux 의 라이브러리 sqrt 호출과 long double 비교

## 문제 요약

v3.5.8, v3.5.8.1, v3.5.8.2 는 `abs(x) <= sqrt(MAX)` 형태의 검사에서 x 의 범위를 배운다.
Mac 에서는 int/int64 square good FP 가 사라졌지만, **Juliet(Linux) 결과는 세 버전 모두
변화가 0** 이었다.

| 버전 | Linux Juliet 변화 |
|---|---|
| v3.5.16 → v3.5.8.1 | 0 |
| v3.5.17 → v3.5.8.2 | 0 |

원인은 Linux clang 의 기본값 `-fmath-errno` 다. 이 설정에서는 `sqrt` 가 LLVM 내장 함수
(`llvm.sqrt`)가 아니라 C 라이브러리 호출로 남는다. 또 x86_64 Linux 의 `long double` 은
80비트라 `sqrtl` 비교가 `fcmp x86_fp80` 이 된다.

```llvm
%11 = call double @sqrt(double 0x41DFFFFFFFC00000)          ; Mac: call @llvm.sqrt.f64
%7  = call x86_fp80 @sqrtl(x86_fp80 0xK403DFFFFFFFFFFFFFFFE)
%8  = fcmp ole x86_fp80 %6, %7                               ; Mac: fcmp ole double
```

pass 는 `llvm.sqrt` 와 half/float/double 비교만 인식해서 이 검사를 모두 건너뛰었다.
`data = INT_MAX`/`LLONG_MAX` 가 함수 인자로 전달되는 good 은 갈 수 없는 분기에서
`error: signed integer overflow` 를 냈다.

---

## 수정

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

1. `bounds()`: 모듈 밖에 선언된 C 라이브러리 `sqrt`(double), `sqrtf`(float),
   `sqrtl`(long double) 호출도 인식한다. 계산하는 범위는 다음과 같다.
   - half/float/double: 실제 제곱근 양옆의 두 표현값
   - 그 밖의 형식: 정수 상·하한

   IEEE 754 의 정확히 반올림된 sqrt 는 물론, 양옆 값 중 하나를 돌려주는(faithful)
   구현도 이 범위 안에 든다. 모듈 안에 정의된 `sqrt` 는 믿지 않는다.
2. `guard()`: float 비교 경로에서 x86 long double, fp128 도 허용한다. 정수 변환 값과
   한계 범위의 정확한 순서 비교만 사용하므로 sound 하다.

호출과 원래 조건은 그대로 둔다.

## 수정 결과

**Mac 에서 `-fmath-errno` 로 Linux 형태 재현 (CWE190 int/int64_t square 432개):**

| | 수정 전 (HEAD) | 수정 후 |
|---|---|---|
| int good FP | 261 | 15 (`_72`~`_74` STL) |
| int64_t good FP | 132 | 91 (fscanf/rand 정당한 경고 + STL) |
| bad | 변화 없음 | 변화 없음 |

**x86_64 Linux 대상 예제:**
- `imaxabs(data) <= sqrtl(LLONG_MAX)` 에 `LLONG_MAX` 전달: error → 경고 없음
- `abs(data) <= (long)sqrt(INT_MAX)` 에 `INT_MAX` 전달: error → 경고 없음
- 입력값(MIN 가능): 정당한 warning 유지

Mac 기본 옵션 결과와 기존 예제 회귀 스위트는 변화가 없다.
