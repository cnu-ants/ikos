# IKOS 3.5.10.2 — (v3.5.10 연장) 작은 signed 타입 산술 결과의 범위 초과 검출

## 문제 요약

v3.5.10.1 은 `char`/`short` 의 `++/--` 결과가 그 타입 범위를 넘으면 signed overflow 로
보고한다. 같은 정책이 일반 산술에는 적용되지 않았다.

```c
char data;                       /* fscanf 입력, 또는 CHAR_MAX */
char result = data + 1;          /* 경고 없음 (미탐). 127 + 1 -> -128 */
char result = data * 2;          /* 경고 없음 */
char result = data * data;       /* 경고 없음 */
```

C 는 이것을 `(char)((int)data + 1)` 로 계산한다. int 덧셈은 넘치지 않고, char 로의
변환이 값을 바꾼다. clang 은 `++` 를 좁은 `add i8` 로 내보내 v3.5.10.1 이 처리한다.
반면 이 경우는 `sext → add nsw i32 → trunc i8` 형태라 적용되지 않았다.

Juliet(Linux, v3.5.18) CWE190 char/short add/multiply/square bad FN 456건
(fscanf/max × 3연산 × 2타입 × 38). 원래 IKOS(v3.5.1)부터 그대로였다.

---

## 수정

**파일:** `frontend/llvm/src/import/function.cpp` — `translate_narrow_signed_trunc()`

`trunc` 를 번역할 때 다음을 모두 만족하면 **그 폭의 signed 연산**(`SAdd`/`SSub`/`SMul`,
no-wrap 없음)으로 번역한다.

- 형태가 `trunc(add|sub|mul(x, y))` 이고 결과 폭이 8/16 비트다.
- x, y 는 결과와 같은 폭에서의 `sext` 이거나, 그 폭의 signed 범위에 드는 상수다
  (둘 다 상수인 경우는 제외).
- 결과가 signed 로 선언됐다는 근거가 있다(결과의 debug 타입, 또는 저장 대상의 선언
  타입). unsigned 라는 근거는 없어야 한다.

Two's complement 에서 넓은 결과를 자르는 것은 좁은 wrap 연산과 **값이 정확히 같다**.
그래서 분석 값은 바뀌지 않고, 결과가 범위를 넘을 때만 signed overflow 를 보고한다.
v3.5.10.1 과 같은 방식으로, 바로 앞에서 읽은 피연산자는 signed 타입으로 다시 읽어
`if (data < CHAR_MAX)` 같은 검사 범위를 유지한다.

char/short square good 의 `abs((long)data) <= (long)sqrt(CHAR_MAX)` 검사는 v3.5.8.4 가
처리한다. 이 버전은 v3.5.8.4 다음에 적용해야 good FP 가 생기지 않는다.

## 수정 결과 (Mac 하네스, CWE190 char/short 1,320개, `RAND32()` 줄 경고 제외)

| 타입/연산 | bad TP | good FP |
|---|---|---|
| char/short add | 0 → 132 (각) | 0 → 9 (각, `_72`~`_74` STL 만) |
| char/short multiply | 0 → 132 (각) | 0 → 9 (각, STL 만) |
| char/short square | 0 → 132 (각) | 0 → 9 (각, STL 만) |
| char/short `++`/`--` | 변화 없음 | 변화 없음 |

- Linux 형태(`-fmath-errno`, io.c 먼저 링크)에서도 같은 결과다.
- int/int64 square 와 CWE126/369/415/457/476 묶음은 변화가 없다.
- STL `_72`~`_74` 의 새 FP 는 컨테이너를 거치며 값을 잃는 기존 한계 때문이다.
  int 의 같은 변형에도 이미 있는 FP 다.
- 기존 예제 회귀 스위트: `g_char` 에서 기존 `might be uninitialized` 경고가 같은 줄에 한 번
  더 출력된다(signed 재로드 문장이 추가된 탓). 판정 변화는 없다.
