# IKOS 3.5.8.1 — (v3.5.8 연장) Juliet 형태의 절댓값·제곱근 조건 인식

## 문제 요약

v3.5.8 은 ikos-pp 의 `prove_constant_float_comparison` 패스로 `abs(x) <= C` 형태의
조건을 찾아, 참 경로에 `-C ≤ x ≤ C` 검사를 덧붙였다. 그러나 Juliet 의 int 제곱 검사는
다음 형태여서 패턴 인식에 실패했고, Juliet 결과에 변화가 없었다.

```c
int data = 0;
fscanf(stdin, "%d", &data);
if (data > INT_MIN && abs(data) < (long)sqrt((double)INT_MAX)) {
  int result = data * data;   // v3.5.8: possible signed integer overflow (오탐)
}
```

---

## 근본 원인

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

1. 비교 왼쪽이 `sext(abs(data))` — `abs` 결과가 long 으로 확장된 뒤 비교돼
   `abs` 호출로 인식되지 않았다.
2. 비교 오른쪽이 `fptosi(llvm.sqrt(C))` — 정수 상수 계산(`constant()`)은 `sqrt` 를
   몰랐고, `sqrt` 범위 계산(`bounds()`)은 부동소수점 비교에서만 쓰였다.
3. `abs(MIN)` 제외 검사(`minimum_excluded`)가 `x != MIN` / `x == MIN` 만 인정했다.
   Juliet 은 `data > INT_MIN` 을 쓴다.
4. `fscanf(&data)` 처럼 주소가 노출된 변수는 `data > INT_MIN` 과 `abs(data)` 가
   같은 주소를 **각각 다시 읽은** 서로 다른 값이라 같은 값으로 보지 못했다.

---

## 수정

1. 비교 왼쪽에서 `sext`/`zext` 를 벗겨 `abs` 를 찾는다. `abs` 입력의 MIN 이 제외된
   경우(아래 검사)에만 적용되므로 `abs` 결과는 0 이상이고 확장은 값을 보존한다.
2. 비교 오른쪽이 `fptosi(S)` 이고 S 가 `sqrt(상수)` 이면, S 의 상한을 0 방향으로 잘라
   한계값으로 쓴다. `fptosi(S) ≤ trunc(상한)` 이므로 sound 하다.
3. 한계값을 `abs` 입력 비트 폭에 맞추고(넘치면 포기), `x > MIN`(참 간선)·`x <= MIN`
   (거짓 간선)도 MIN 제외로 인정한다.
4. 같은 주소를 두 번 읽은 단순 load 는, 같은 블록이거나 두 번째 블록의 유일한 선행 블록이
   첫 번째 블록이고 그 사이에 메모리를 쓸 수 있는 명령이 없으면 같은 값으로 본다.

## 정당한 경고로 분류한 것 (수정하지 않음)

- **int64_t square** `if (imaxabs((intmax_t)data) <= sqrtl(LLONG_MAX))`:
  `INT64_MIN` 제외 검사가 없다. `imaxabs(INT64_MIN)` 은 UB 이고, 실제 구현은 음수를
  돌려주므로 조건을 통과해 `data * data` 가 오버플로한다. Juliet good 이지만 경고는 정당하다.
  (Linux 에서는 `sqrtl` 이 80비트 long double 이라 패스가 지원하지 않는 점도 있다.)
- **unsigned int square** `if (abs((long)data) < (long)sqrt((double)UINT_MAX))`:
  `abs` 는 int 를 받으므로 큰 unsigned 값(예: 4294967291)이 int 로 잘려(-5) 검사를
  통과하고 `data * data` 가 오버플로한다. 경고는 정당하다.
- **char/short square**: sink(`data * data`)는 int 로 계산돼 오버플로가 없다. 남은 FP 는
  입력 매크로 `RAND32()` 줄의 unsigned 부호 반전 경고(별도 항목)다.
