# IKOS 3.5.5.1 — (v3.5.5 연장) unsigned 지역 변수의 검사 후 재로드

## 문제 요약

v3.5.5 는 "메모리 칸과 거기서 읽은 값은 같다"는 복사 관계를 정수 도메인에 추가해,
검사로 좁힌 범위가 재로드에도 유지되게 했다. 그러나 **unsigned** 지역 변수에서는
동작하지 않았다.

```c
unsigned int data = 0;
fscanf(stdin, "%u", &data);
if (data < UINT_MAX) {
  unsigned int result = data + 1;   // v3.5.5: possible unsigned integer overflow (오탐)
}
```

`if (data < 100)` 처럼 작은 상수와 비교해도 같은 오탐이 났다. signed 변수와
레지스터(SSA) unsigned 값은 정상이었다.

---

## 근본 원인

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp` — `exec(ar::Allocate*)`

- 메모리 칸 변수는 (주소, 오프셋, 크기)로 한 번 만들어지면 부호가 바뀌지 않는다
  (`VariableFactory::get_cell`).
- 지역 변수를 할당하면 미초기화 표시를 위해 `undefined` 값을 먼저 쓰는데,
  `undefined` 의 선호 부호가 **signed** 라서 모든 정수 지역 변수의 칸이 signed 로 만들어졌다.
- unsigned 로 읽은 값과 signed 칸은 부호가 달라 복사 관계가 맺어지지 않는다
  (`CompositeDomain::dynamic_read_int` 는 같은 부호일 때만 `assign`).
  또 signed 칸에는 "UINT_MAX 제외" 같은 unsigned 범위를 표현할 수 없다.

---

## 수정

정수 스칼라 지역 변수(`allocate iN, 1`, 크기가 타입 폭과 같음)를 할당할 때,
`undefined` 를 쓰기 전에 **선언된 타입의 부호로 칸을 먼저 만든다**.
이후 동작(미초기화 표시, 읽기/쓰기)은 그대로다.

---

## 수정 결과

- 예제: unsigned `fscanf` 입력 후 `x < UINT_MAX` / `x < 100` 검사, 외부 함수가 쓴
  unsigned 값 — 오탐 사라짐. signed·레지스터 값은 변화 없음.
- Juliet A/B (Mac, 이 수정만 켜고 끔):
  - CWE190 unsigned_int fscanf add/multiply/preinc/postinc: good 오탐 36개 사라짐, bad 경고 유지.
  - CWE369, CWE457, CWE126, CWE415, CWE476 샘플(약 130 프로그램): 진단 변화 없음.
- 기존 예제: unsigned 검사 예제 1건의 오탐만 사라짐.
