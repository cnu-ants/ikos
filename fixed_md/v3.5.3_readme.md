# IKOS 3.5.100 — double 스칼라의 참조·포인터 읽기 미초기화 누락 수정

## 문제 요약

초기화하지 않은 `double` 스칼라를 참조·포인터 경유로 읽으면
미초기화 변수 검사(`uva`)가 진단을 누락하는 문제가 있었다.
같은 구조에서 `int`는 미초기화 오류를 탐지했다.

```c
#include <stdio.h>

void sink(double* data) {
  printf("%g\n", *data);  // 수정 전: safe → 수정 후: error
}

int main(void) {
  double data;
  sink(&data);
  return 0;
}
```

`sink(&data)`에서 변수의 주소를 전달하는 것은 유효하다.
진단 대상은 `sink()` 내부에서 초기화되지 않은 `*data`를 읽어 사용하는 부분이다.
C++에서 `double&`로 전달하여 읽는 경우에도 같은 메모리 읽기 문제가 발생한다.

---

## 근본 원인

원래 미탐의 직접 원인은 부동소수점 메모리 읽기 결과에 원본의 초기화 상태를
전달하지 않는 것이었다. 이를 수정한 뒤에는 기존 `calloc` 모델의 초기화 정보
누락이 오탐으로 드러나, 해당 경로도 함께 보완했다.

### 원인 1 — double 메모리 읽기가 결과를 무조건 초기화 상태로 설정

**파일:** `core/include/ikos/core/domain/memory/value.hpp`

**함수:** `LiteralReader::floating_point_var()`

기존 코드는 메모리 셀 `_rhs`를 부동소수점 변수 `lhs`로 읽을 때
`float_assign_nondet(lhs)`만 호출했다.

```cpp
void floating_point_var(VariableRef lhs) {
  this->_scalar.float_assign_nondet(lhs);
}
```

**파일:** `core/include/ikos/core/domain/scalar/composite.hpp`

**함수:** `float_assign_nondet()`

이 연산은 값의 수치 정보를 임의의 값으로 처리하면서,
초기화 상태는 명시적으로 초기화됨으로 설정한다.

```cpp
this->_uninitialized.assign_initialized(x);
```

따라서 원본 메모리 셀이 미초기화 상태여도 읽기 결과는 초기화된 것으로 바뀐다.
이후 `printf()` 인수를 검사하는 초기화 검사기가 이 결과를 안전하다고 판단했다.

반면 정수 메모리 읽기의 `dynamic_read_int()`는 원본 셀의 초기화 상태를 복사한다.

```cpp
this->_uninitialized.assign(x, y);
```

이 차이 때문에 동일한 포인터 전달 구조에서도 `int`는 오류를 탐지하고,
`double`은 진단을 누락했다.

### 원인 2 — calloc의 초기화된 메모리가 읽을 수 있는 셀로 기록되지 않음

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `exec_calloc()`

**파일:** `core/include/ikos/core/domain/memory/value.hpp`

**함수:** `mem_zero_reachable()`

`exec_calloc()`은 할당 영역을 `MemoryInitialValue::Zero`로 지정하지만,
값 메모리 도메인의 `mem_zero_reachable()`은 다음과 같이 구현되어 있다.

```cpp
void mem_zero_reachable(VariableRef p) override {
  this->mem_uninitialize_reachable(p);
}
```

이 경로는 기존 메모리 정보를 제거하며, 새 영역이 초기화되어 있다는 정보를
메모리 셀로 만들지 않는다. 그 결과 해당 영역을 읽으면 초기화 여부가 불확실한
상태가 나올 수 있다.

기존 부동소수점 읽기는 결과를 무조건 초기화 상태로 바꿔 이 문제를 가렸다.
원인 1을 수정하자 불확실한 상태가 그대로 전달되어, 다음과 같은 정상 코드에
미초기화 가능성 경고가 발생했다.

```c
double* data = calloc(1, sizeof(*data));
if (data) {
  printf("%g\n", *data);  // 초기화된 메모리이므로 미초기화 진단이 없어야 함
}
free(data);
```

## 수정 내용

### 수정 1 — 원본 메모리 셀의 초기화 상태를 부동소수점 읽기 결과에 전달

**파일:** `core/include/ikos/core/domain/memory/value.hpp`

**함수:** `LiteralReader::floating_point_var()`

```cpp
// 수정 전
void floating_point_var(VariableRef lhs) {
  this->_scalar.float_assign_nondet(lhs);
}

// 수정 후
void floating_point_var(VariableRef lhs) {
  this->_scalar.float_forget(lhs);
  this->_scalar.uninit_refine(
      lhs, this->_scalar.uninit_to_uninitialized(this->_rhs));
}
```

처리 순서는 다음과 같다.

1. `float_forget(lhs)`로 목적 변수의 기존 정보를 제거한다.
   초기화 상태도 TOP(초기화 여부 불확실)으로 만든다.
2. 원본 셀 `_rhs`의 초기화 상태를 조회한다.
3. TOP인 목적 변수에 원본 상태를 반영하여 미초기화·초기화·불확실 상태를 보존한다.

목적 변수를 먼저 TOP으로 만들기 때문에 `uninit_refine()`이 원본 상태를
복사하는 효과를 낸다. 이미 초기화됨으로 설정한 값에 미초기화 상태를 교차 적용해
분석 상태가 bottom으로 바뀌는 문제도 피한다.

부동소수점의 수치 정보는 계속 추상화한다. 다른 경로에서도 사용하는
`float_assign_nondet()`의 기존 의미와 스칼라 도메인 API는 변경하지 않았다.

### 수정 2 — calloc이 보장하는 초기화 범위를 메모리 셀로 기록

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `exec_calloc()`

`count`와 `size`가 상수이면 그 값을 사용하고, 정수 변수이면 현재 추상 상태에서
각각의 구간 하한을 구한다. 두 하한의 곱으로 성공한 할당에서 확실히 초기화되는
바이트 수를 계산하고, 그 범위를 초기화된 메모리 셀로 기록한다.

핵심 추가 코드는 다음과 같다. `count_lb`와 `size_lb`는 위에서 구한 하한이다.

```cpp
if (count_lb && size_lb) {
  bool overflow;
  MachineInt initialized_size = mul(*count_lb, *size_lb, overflow);
  if (!overflow && !initialized_size.is_zero() &&
      (initialized_size.to_z_number() * 8).fits< uint64_t >()) {
    auto nullity = this->_inv.normal().nullity_to_nullity(lhs.var());
    this->_inv.normal().nullity_set(lhs.var(), Nullity::non_null());
    this->_inv.normal().mem_write(lhs.var(),
                                  ScalarLit::machine_int(
                                      MachineInt::zero(8, Unsigned)),
                                  initialized_size);
    this->_inv.normal().nullity_set(lhs.var(), nullity);
  }
}
```

- 기록하는 크기는 보장된 초기화 범위이다. 하한을 알 수 없거나 곱셈이
  오버플로하는 경우, 크기가 0인 경우, 셀의 비트 폭을 표현할 수 없는 경우에는
  이 초기화 셀을 추가하지 않는다.
- 8비트 0 리터럴보다 넓은 셀은 기존 `mem_write()`의 크기 불일치 처리에 따라
  초기화된 임의의 정수 값으로 기록된다. 이 보완은 바이트 전체가 초기화됐다는
  정보를 전달하며, 넓은 셀의 수치 값이 0이라는 정밀도까지 추가하지 않는다.
- 메모리 셀 기록 시에만 반환 포인터를 non-null로 설정하고, 기록 후에는 기존
  nullity를 복원한다. 따라서 `calloc()`의 NULL 반환 가능성과 할당 실패 경로를 유지한다.
- 이 처리는 `UpdateAllocSizeVar` 검사 이전에 수행한다. `-a=uva`만 활성화하여
  할당 크기 변수를 별도로 추적하지 않는 경우에도 초기화 정보를 기록한다.

### 수정 3 — 참조·포인터 읽기와 calloc 회귀 테스트 추가

**파일:** `analyzer/test/regression/uva/runtest`

**테스트 파일:** `analyzer/test/regression/uva/test-40-error.c`부터
`test-52-error.c`까지의 C/C++ 테스트 13개

다음 항목을 포함한 총 25개 테스트 구성을 등록했다.

- 포인터 경유 `double`의 미초기화·초기화·조건부 초기화 상태
- 초기화·미초기화 변수를 함께 가리킬 수 있는 포인터
- `float`의 미초기화 읽기
- `calloc()`의 상수 크기 및 양의 하한을 갖는 가변 개수 할당
- `calloc()` 실패 분기의 도달 가능성과 NULL 검사 누락 경고
- C++ 참조 경유 `double`의 미초기화·초기화·조건부 초기화 상태
- `malloc()`으로 할당한 미초기화 `double`의 읽기

각 테스트는 진단 대상 줄의 상태도 검사한다. 정상 초기화 사례에서는 해당 줄이
안전하고 도달 가능한지 확인한다. `float` 사례를 제외한 추가 테스트는
`basic`·`none` 양쪽 전처리 설정으로 실행한다.

### 검증 결과

- 이번 문제에 추가한 관련 테스트 구성 **25개 모두 통과**했다.
- 기존 UVA 테스트를 포함한 검증에서는 **58개 통과, 진단 불일치 0개**였다.
- 기존 C++ 테스트 `test-33-error.cpp`부터 `test-36-error.cpp`까지 4개는
  LLVM 가져오기 단계에서 실행 오류가 발생했다. 수정 전에도 같은 실행 오류가
  발생했으며, 이 4개는 통과 개수에 포함하지 않았다.
- `git diff --check`를 통과했다.

### 적용 범위

이번 수정은 `double` 스칼라를 참조·포인터 경유로 읽을 때 초기화 상태가
누락되는 문제와, 해당 변경으로 드러난 `calloc()` 초기화 정보 누락을 다룬다.
가변 배열 인덱스·반복문의 범위 오프셋 읽기에서 발생하는 미초기화 미탐은
별도 이슈로 관리한다.
