# IKOS 3.5.11.2 — (v3.5.11 연장) double 범위 밖 long double 상수 비교의 0 판정

## 문제 요약 (soundness)

v3.5.11.1 은 `x > c`, `x != 0.0` 같은 부동소수점 비교에서 "x ≠ 0" 을 배운다. 이때 쓰는
것은 상수 `c` 의 **부호와 0 여부**뿐이고, 상수 텍스트를 `strtod` 로 double 로 읽어
판단했다.

x86_64 Linux 에서 `long double` 은 80비트라 double 보다 훨씬 작은 수를 표현한다.
이런 상수는 `strtod` 에서 언더플로해 **±0.0 이 된다**.

```c
long double x;              /* x == 0 가능 */
if (x > -1e-4900L) {        /* strtod: -1e-4900 -> -0.0 → "x > 0" 으로 오인 */
    r = 1.0L / x;           /* v3.5.11.1: 경고 없음 (미탐). x = 0 도 이 조건을 통과한다 */
}
```

`x > -0.0` 은 `x > 0` 과 같으므로 "x ≠ 0" 으로 잘못 결론 냈다. 실제 상수는 음수이므로
x = 0 도 조건을 통과한다. Mac(arm64)은 `long double` 이 double 과 같아 생기지 않는다.
Juliet 에는 이런 상수가 없다.

---

## 수정

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp` —
`refine_float_comparison()`

- 읽은 값이 0 이라도 상수 텍스트의 가수부에 0 이 아닌 숫자가 있으면, 텍스트의
  부호를 가진 0 이 아닌 값으로 본다. 규칙이 부호와 0 여부만 쓰므로 정확하다.
  오버플로(±inf)도 부호가 유지된다.
- 텍스트 끝까지 읽지 못한 상수는 사용하지 않는다.
- v3.5.11.1 에서 함수를 끼워 넣다가 `exec_float_comparison` 의 주석 한 줄이 떨어져
  나간 것을 제자리로 옮겼다.

## 수정 결과

x86_64 대상으로 컴파일한 예제:

| 조건 | v3.5.11.1 | v3.5.11.2 |
|---|---|---|
| `x > -1e-4900L` 뒤 `1/x` (x=0 가능) | 경고 없음 (미탐) | warning |
| `x > 1e-4900L` 뒤 `1/x` | 경고 없음 | 경고 없음 |
| `d > -0.0`, `d > 0.5`, `f != 0.0f` | 경고 없음 | 경고 없음 |
| `d >= 0.0` | warning | warning |

일반 범위 상수의 판정은 바뀌지 않는다. 기존 예제 회귀 스위트도 변화가 없다.
