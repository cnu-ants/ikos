# IKOS 3.5.102 — 참조로 주소가 노출된 정수의 검사 후 재로드 오탐 수정

## 문제 요약

참조·포인터를 통해 주소가 노출된 정수 지역 변수를 검사한 뒤 배열 인덱스로
사용하면, 기본 `interval` 도메인에서 가능한 버퍼 오버플로 경고가 발생했다.
조건에서 인덱스를 `[0, 9]`로 제한했는데도 다음 메모리 읽기에 그 범위가 전달되지 않았다.

```cpp
#include <stdio.h>
#include <limits.h>

void source(int& data) {
  fscanf(stdin, "%d", &data);
}

void test() {
  int data = -1;
  source(data);
  int buffer[10] = {0};
  if (data >= 0 && data < 10) {
    printf("%d\n", buffer[data]);  // 수정 전: possible buffer overflow
  }
}

int main() {
  test();
  return 0;
}
```

이 문제는 `fscanf()`의 입력값을 정확히 예측해야 해결되는 문제가 아니다.
입력 후 값이 임의의 정수여도, 조건문을 통과한 경로에서는 인덱스가 유효한 범위에 있다.

이번 수정으로 위 `buffer[data]` 접근은 `basic`과 `none` 양쪽에서 안전하게 판정된다.
`fscanf()`에 전달한 `stdin`의 주소 정보에 대한 별도 경고는 남아 있다.

## 근본 원인

### 원인 — 비관계형 정수 도메인에서 메모리 셀과 복사본의 동일성 유실

**파일:** `core/include/ikos/core/domain/machine_int/separate_domain.hpp`

**함수:** `SeparateDomain::assign()`, `refine()`

**관련 파일:** `core/include/ikos/core/domain/scalar/composite.hpp`

**관련 함수:** `dynamic_write_int()`, `dynamic_read_int()`

정수 메모리 읽기·쓰기는 스칼라 도메인을 통해 정수 도메인의 `assign(x, y)`를
사용한다. 기존 구현은 원본의 현재 추상 값만 복사했다.

```cpp
// 수정 전
void assign(VariableRef x, VariableRef y) {
  this->set(x, this->get(y));
}
```

기본 `interval` 도메인은 각 변수의 구간을 독립적으로 저장한다.
따라서 같은 메모리에서 읽은 값이라는 관계가 사라지고, 읽기 결과에 조건을
적용해도 원본 메모리 셀이나 다른 읽기 결과의 범위는 좁아지지 않았다.

주소가 노출된 `data`는 메모리에 남으며, 조건과 배열 접근이 각각 별도의 load를
사용할 수 있다. 재현한 AR의 핵심 흐름은 다음과 같다.

```text
v1 = load cell
assume(v1 >= 0)       // v1만 [0, INT_MAX]

v2 = load cell
assume(v2 < 10)       // v2만 [INT_MIN, 9]

v3 = load cell       // cell이 제한되지 않았으므로 v3는 전체 정수 범위
value = buffer[v3]   // 가능한 버퍼 오버플로 경고
```

`--opt=none`에서만 발생하는 문제는 아니었다. 재현 예제에서는 `basic`에서도
이 load들이 남아 같은 오탐이 발생했다.

수정 전에도 관계형 `dbm` 도메인으로 분석하면 해당 배열 접근은 안전했다.
이는 기본 비관계형 도메인이 복사 관계를 표현하지 못하는 정밀도 한계가
메모리 재로드에서 드러난 사례이다. 이번에는 단순 복사 동일성을 추적하도록
도메인을 확장하여 보완했다.

### fscanf 처리와의 관계

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**관련 경로:** `ar::Intrinsic::LibcFscanf` → `exec_unknown_call()`

기존 분석기는 `fscanf()`를 인식하고, 포인터 인수가 가리키는 메모리가
변경될 수 있는 호출로 처리한다. 이 예제의 입력 후 `data` 값이 불확실해지는
것은 적절한 추상화이다.

누락된 부분은 입력값의 모델이 아니라, 이후 조건에서 얻은 범위를 변경되지 않은
동일 메모리의 재로드에 전달하는 관계였다. 이번 수정에서 `fscanf()` 모델은 변경하지 않았다.

## 수정 내용

### 수정 1 — 기계 정수의 단순 복사 관계 보존

**파일:** `core/include/ikos/core/domain/machine_int/separate_domain.hpp`

`SeparateDomain`에 `_copies`를 추가하여 값이 동일한 복사본들을 기록한다.
기존 변수별 추상 값은 유지하면서 복사 동일성을 함께 추적한다.

```cpp
void assign(VariableRef x, VariableRef y) {
  if (this->is_bottom() || x == y) {
    return;
  }
  this->set(x, this->get(y));
  if (VariableTrait::bit_width(x) == VariableTrait::bit_width(y) &&
      VariableTrait::sign(x) == VariableTrait::sign(y)) {
    this->merge_copies(CopySet{x, y});
  }
}
```

- 비트 폭과 부호가 같은 정수의 단순 대입에서 복사 관계를 만든다.
- `refine()`은 제약을 같은 복사 관계의 모든 변수에 전달한다.
- 기존 정수 메모리 읽기·쓰기 경로가 이 대입 연산을 사용하므로, 메모리 셀과
  읽기 결과도 연결된다. `composite.hpp`의 읽기·쓰기 코드는 변경하지 않았다.
- 값이 하나의 상수로 확정되면 명시적인 복사 관계는 제거한다.
  같은 상수 값 자체가 동일성을 표현하며, 필요한 경우 합류 시 이를 고려한다.

수정 후 위 예제에서는 첫 번째 검사로 원본 셀이 0 이상으로 제한되고,
두 번째 검사로 셀과 읽기 결과가 `[0, 9]`로 좁아진다.
배열 접근에 사용하는 세 번째 load도 이 범위를 전달받는다.

3.5.101의 포인터 수정은 NULL 여부가 같은 관계를 추적했다.
이번 수정은 기계 정수 값 자체가 같은 관계를 추적한다.

### 수정 2 — 덮어쓰기·forget과 분기 합류에서 관계 관리

**파일:** `core/include/ikos/core/domain/machine_int/separate_domain.hpp`

- `set()`과 `forget()`은 대상 변수를 기존 복사 관계에서 분리한다.
  나머지 복사본들 사이의 유효한 관계는 유지한다.
- 상수 대입·산술 연산 등 기존 `set()` 경로를 사용하는 값 변경도 이전 관계를 해제한다.
- `join`과 `widening`에서는 양쪽 상태에서 모두 성립하는 동일성만 유지한다.
  양쪽의 확정 상수로부터 성립하는 동일성도 고려한다.
- `meet`와 `narrowing`에서는 관계를 결합하고, 연결된 변수들의 추상 값을 교차하여 전파한다.
- `is_top()`, `leq()`, `equals()` 및 상태 출력도 추가된 관계를 반영한다.

따라서 다음처럼 검사 뒤 값이 바뀔 수 있는 접근은 계속 경고해야 한다.

```cpp
extern void rewrite(int*);

void use(int data) {
  int buffer[10] = {0};
  if (data >= 0 && data < 10) {
    rewrite(&data);             // 이전 검사 범위가 더 이상 보장되지 않음
    printf("%d\n", buffer[data]);  // warning 유지
  }
}
```

메모리 변경은 기존 메모리 쓰기·무효화 경로를 통해 관계에서 분리된다.
외부 호출의 기존 메모리 변경 가정을 새로 강화하거나 제거한 수정은 아니다.

### 수정 3 — 조건 제약을 대입과 구분하여 처리

**파일:** `core/include/ikos/core/domain/machine_int/interval.hpp`

**파일:** `core/include/ikos/core/domain/machine_int/congruence.hpp`

**파일:** `core/include/ikos/core/domain/machine_int/interval_congruence.hpp`

조건 검사와 일부 `refine()` 구현이 사용하던 내부 `set()`을 `refine()`으로 변경했다.
기존에는 독립적인 변수 값만 저장했으므로 제약 반영에도 `set()`을 사용할 수 있었다.
복사 관계를 추가한 뒤에는 대입과 제약을 구분해야 한다.

```cpp
// 조건에 따른 범위 제한의 예
// 수정 전
this->_inv.set(x, i);

// 수정 후
this->_inv.refine(x, i);
```

`set()`은 변수에 새 값을 대입하여 이전 관계를 해제한다.
`refine()`은 기존 값에 제약을 추가하여 유효한 관계를 유지하고 결과를 전파한다.
이 구분을 `interval`, `congruence`, `interval-congruence` 도메인에 적용했다.
합동식만 표현하는 `congruence` 도메인이 일반적인 구간 제약까지 표현하게 된 것은 아니다.

## 수정 결과

아래 표는 기본 `interval` 도메인에서 해당 배열 접근의 판정이다.
프로그램 전체의 모든 경고가 사라졌다는 의미는 아니다.

| 케이스 | 수정 전 basic / none | 수정 후 basic / none |
|--------|:--------------------:|:--------------------:|
| 원래 예제의 `buffer[data]` | **warning / warning** | **safe / safe** |

임시 벤치마크에서는 다음 범위를 `interval`과 `interval-congruence` 각각의
`basic`·`none` 설정으로 확인했다.

| 구분 | 사례 | 수정 후 결과 |
|------|------|-------------|
| 안전 사례 8개 | 참조·포인터, 구조체 필드, 배열 원소, 조기 반환, 저장한 복사본, 반복문 내부 검사 | 모두 진단 없음 |
| 위험 사례 12개 | 검사 없음, 한쪽 경계만 검사, 범위 밖 조건, 검사 후 재대입·외부 변경, 다른 변수 검사, 약한 메모리 쓰기 등 | 모두 진단 유지 |
| 확정 범위 초과 | 검사 후 인덱스를 10으로 대입하거나 `[10, 19]`로 제한 | **error 유지** |

### 검증 결과

- 정수 도메인 기존 단위 검사: **51개 통과**
  (`interval`, `congruence`, `interval-congruence` 각각 17개).
- 기존 BOA 구성: **128개 통과**, **3개 기존 실행 오류**.
  `test-51.c`, `test-51-unsafe.c`, `test-56.cpp`는 수정 전 분석기에서도
  같은 종료 코드의 실행 오류가 발생했다. `test-51.c`에서는 지원하지 않는
  LLVM `va_arg` 명령으로 가져오기 단계가 실패하는 것을 확인했다.
- 기존 메모리 검사 **52개**, NULL 검사 **14개**, signed/unsigned overflow 검사
  **9개**, 앞서 수정한 부동소수점 미초기화 관련 검증 구성 **25개**가 통과했다.
- 이전 NULL 검사 벤치마크의 `basic`·`none` 진단 위치·상태가 유지됐다.
- 임시 도메인 검증에서 3비트 정수 변수 3개의 구체 상태 512개를 열거하여,
  대입·제약·forget 등의 연산 1,200회와 상태 쌍 3,000개의 합류·교차·
  포함 관계·widening·narrowing을 검사했다.
- 빌드 및 `git diff --check`를 통과했다.

프로젝트에 새 회귀 테스트 파일을 추가하거나 기존 테스트를 수정하지 않았다.
추가 검증용 코드와 실행 결과는 프로젝트 밖의 임시 디렉터리에 두었다.

## 적용 범위와 한계

이번 수정은 동일한 기계 정수의 단순 복사 관계를 통해 검사 결과를 전달하는 보완이다.
참조·포인터로 주소가 노출되어도, 변경되지 않은 셀과 그 읽기 결과가 복사 관계로
연결되면 조건에서 얻은 범위를 후속 재로드에 전달한다.

다음 범위까지 일반적으로 해결됐다고 보장하지는 않는다.

- 비트 폭·부호가 달라지는 타입 변환이나 일반적인 산술식 사이의 관계.
- 여러 메모리 대상·범위 주소 등으로 인해 동일 셀과의 복사 관계를 유지하지 못하는 경우.
- 서로 다른 변수 사이의 일반적인 부등식이나 복잡한 경로 상관관계.
- `fscanf()`의 형식 문자열·반환값·입력 성공 여부에 대한 정밀한 모델링.

재현 환경에서는 `fscanf()`에 전달되는 `stdin` 포인터에 points-to 정보가 없다는
별도 BOA 경고가 남았다. 이번 배열 인덱스 재로드 문제와 분리하여 관리한다.
복사 관계를 추가했으므로 기존 도메인보다 상태 관리와 합류 비용도 늘어날 수 있다.
전체 프로그램에 대한 성능 영향은 이번 기능 검증만으로 확정하지 않는다.
