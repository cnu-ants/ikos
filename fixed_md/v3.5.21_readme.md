# IKOS 3.5.21 — (v3.5.12 보완) x86_64 의 프로토타입 없는 호출과 초기화 증명

## 문제 요약

Juliet CWE457 `_12` 의 포인터 변형(`int_pointer_12`, `double_pointer_12`)은 goodG2B 에서 두
분기 모두 malloc 후 값을 저장한다. 그런데 Linux 결과에서만 읽기 지점에 오탐이 남았다.

```c
int *data;
if (globalReturnsTrueOrFalse()) { data = malloc(sizeof(int)); if (!data) exit(-1); *data = 5; }
else                            { data = malloc(sizeof(int)); if (!data) exit(-1); *data = 5; }
if (globalReturnsTrueOrFalse()) printIntLine(*data);   // Linux: might be uninitialized
else                            printIntLine(*data);
```

Mac(arm64)에서는 나오지 않고, `-target x86_64-apple-macos11` 로 컴파일하면 재현된다.

## 원인

**파일:** `analyzer/src/analysis/initialization.cpp` — `InitializationProof::preserves_memory()`

v3.5.12 의 초기화 증명은 저장과 읽기 사이의 호출이 메모리를 바꾸지 않는지 확인한다.
Juliet 은 `globalReturnsTrueOrFalse` 를 프로토타입 없이(`int f();`) 선언한다. x86_64 에서는
이런 호출이 `call i32 (...) bitcast (@f ...)()` 로 생성된다(v3.5.17.1 과 같은 형태).
`getCalledFunction()` 이 null 을 돌려주므로 "메모리를 바꿀 수 있는 알 수 없는 호출"로
보고 증명을 포기했다.

## 수정

`preserves_memory()` 에서 호출 대상의 포인터 cast 를 벗겨 함수를 찾는다. 여기서는 호출된
함수의 **본문**만 검사하므로(인자 연결은 쓰지 않음) 호출 시그니처가 달라도 결과가 같다.
호출자 인자 연결을 쓰는 다른 경로(반환 메모리 추적, 호출 문맥 바인딩)는 인자 개수가 어긋날
수 있어 그대로 둔다.

## 수정 결과

- x86_64 대상 컴파일: `int_pointer_12`·`double_pointer_12` goodG2B 오탐 해소, bad 검출 유지.
- `struct_pointer_12` 의 `data->intTwo` 경고는 Mac 에서도 나오는 별개 문제라 남는다.
- Mac 기존 결과, 회귀 스위트 4종, CWE457 C 파일 560개: 변화 없음.
