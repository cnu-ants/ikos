# IKOS 3.5.10.1 — (v3.5.10 연장) 작은 signed 타입 증감의 범위 초과 검출

## 문제 요약

v3.5.10 은 `char`·`short` 의 `++/--` 를 unsigned 덧셈으로 번역하던 오탐을 고쳐,
C 의미론대로 한 비트 넓은 signed 정수로 계산한 뒤 잘라내도록 했다. 이 방식에서는
`127 + 1` 이 9비트에서 정상 값이라 어떤 경고도 나오지 않는다.

그 결과 검사 없이 증가시키는 Juliet bad 도 경고가 사라졌다.

```c
char data;
fscanf(stdin, "%c", &data);
++data;                     // v3.5.10: 경고 없음 (미탐). 127 이면 -128 로 바뀐다.
```

Juliet (Linux, v3.5.9 → v3.5.10) CWE190 char/short `++` bad 156개가 TP → FN.

---

## 근본 원인과 정책

**파일:** `frontend/llvm/src/import/function.cpp` — `translate_narrow_signed_update()`

C 에서 `++c` 는 `(char)((int)c + 1)` 이다. 결과가 `char` 범위를 넘으면 값이 조용히
바뀌는데(구현 정의 변환, 127 → -128), 이것은 CWE-190 이 다루는 정수 오버플로다.
v3.5.10 은 이를 UB 가 아니라는 이유로 보고하지 않았다.

**정책 (v3.5.10.1):** 작은 signed 타입의 `++/--` 결과가 그 타입 범위를 넘으면
signed integer overflow 로 보고한다. unsigned 작은 타입은 영향 없음.

또한 메모리 변수(`fscanf(&data)`)의 `++` 는 피연산자를 unsigned 로 다시 읽은 뒤
signed 로 바꾸면서, `if (data < CHAR_MAX)` 로 좁힌 signed 범위를 잃었다.

---

## 수정

1. 작은 signed 타입의 `++/--` 를 **그 타입 폭의 signed 덧셈/뺄셈**(`SAdd`/`SSub`)으로
   번역한다. 범위가 좁혀져 있으면(`data < CHAR_MAX`) 경고가 없고, 없으면 `127 + 1` 이
   가능해 signed overflow 를 보고한다.
2. 피연산자가 같은 블록에서 바로 앞에 읽은 load 이고 그 사이에 메모리를 쓰는 명령이
   없으면, 같은 주소를 signed 타입으로 다시 읽어 쓴다(같은 값). 좁혀진 signed 범위가
   유지된다.
