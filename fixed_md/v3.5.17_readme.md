# IKOS 3.5.17 — 값이 바뀌지 않는 전역 조건 분기 접기

## 문제 요약

v3.5.13(초기화 승격)·v3.5.14(배열 루프 초기화 증명)는 **LLVM 제어 흐름을 보고**
"이 변수/배열은 읽기 전에 반드시 초기화된다"를 증명한다. 그런데 Juliet 의 전역 조건
변형은 초기화와 읽기를 각각 `if` 로 감싼다.

```c
static int staticTrue = 1;       /* _05 */

int data[10];
if (staticTrue) {
    for (i = 0; i < 10; i++) data[i] = i;   /* 초기화 */
}
if (staticTrue) {
    printIntLine(data[0]);                 /* 읽기 */
}
```

값 분석은 `staticTrue` 가 항상 1 이라 거짓 쪽 경로가 없음을 안다. 하지만 위 증명들은
값을 보지 않고 CFG 만 보기 때문에 "초기화를 건너뛰는 경로"가 있다고 판단하고 증명을
포기한다. 그래서 good 함수에 미초기화 읽기 경고가 남았다.

Juliet (v3.5.13 → v3.5.14) CWE457 지역 배열 good FP 중 전역 조건 변형
(`_05`, `_07`~`_11`, `_13`, `_14`) 이 이 경우다. v3.5.14.1 과 원인이 다르므로
별도 버전으로 다룬다.

---

## 수정

**새 ikos-pp pass:** `frontend/llvm/src/pass/fold_constant_global_branches.cpp`
(`-opt=basic` 의 첫 pass)

1. 값이 바뀌지 않는 정수 전역을 모은다. 확정 초기값(`ConstantInt`)이 있고 다음 중
   하나를 만족해야 한다.
   - LLVM `constant` 다 (`const int GLOBAL_CONST_TRUE = 1`).
   - 모듈 안에서 단순 load 로만 쓰인다(store·주소 유출 없음). 내부 링크(`static`)이거나,
     모듈이 `main` 을 정의하는 전체 프로그램이어야 한다. `main` 이 없는 라이브러리에서는
     외부 전역을 다른 번역 단위가 쓸 수 있으므로 접지 않는다.
2. 본문이 `return <상수>` 뿐인 함수를 모은다. 정의가 있고, interposable 하지 않고,
   가변 인자가 아니어야 한다(`globalReturnsTrue()`).
3. 조건 분기의 조건을 위 값과 상수, 정수 변환, `icmp` 로 계산한다. 상수가 되면
   무조건 분기로 바꾼다. 호출 자체는 지우지 않으므로 호출 대상이나 호출에서 나오는
   진단은 그대로 남는다.

값 분석이 이미 도달 불가로 판정하던 간선만 지우므로 분석 결과의 의미는 바뀌지 않는다.
뒤따르는 문법적 증명(초기화 승격, 루프 초기화)이 실제 제어 흐름을 보게 될 뿐이다.

## 수정 결과 (Mac 하네스)

- CWE457 지역 배열 good FP: `_05`, `_07`~`_11`, `_13`, `_14` 해소.
  `_12`(무작위 조건), `_17`, `_43`, `_62`~`_64`(함수 간 참조 전달)는 남는다.
  이 변형들은 접을 조건이 아니라서 이번 수정 범위 밖이다.
- 같은 Juliet 묶음 A/B(pass 켬/끔, CWE190/369/476/457/126/415) 비교:
  - CWE457: good 경고 8건 제거.
  - 나머지 CWE: bad/good 판정 변화 없음.
  - CWE476 전역 조건 변형 16개: bad 의 경고 메시지가 `pointer 'data' is null` 에서
    `pointer is null` 로 바뀐다. 분기가 접혀 `data` 가 상수 `null` 로 승격됐기 때문이다.
    같은 줄의 error 는 그대로이고, Juliet 채점은 메시지가 아니라 소스 줄로 하므로 영향이 없다.
- 기존 예제 회귀 스위트(suite2/457/17/67): 변화 없음.
- `main` 이 없는 모듈: `static`·`const` 전역 조건만 접히고 외부 전역 조건은 남는 것을 확인했다.
