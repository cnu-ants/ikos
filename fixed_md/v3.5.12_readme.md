# IKOS 3.5.109 — 분기별 malloc 후 스칼라 읽기의 미초기화 오탐 보완

## 문제 요약

각 if/else 분기에서 메모리를 할당하고 값을 초기화했는데도, 분기 합류 후
포인터를 역참조하면 미초기화 가능성을 보고하는 문제가 있었다.

사용자가 처음 제시한 원본 예제는 다음과 같다.

```c
#include <stdio.h>
#include <stdlib.h>

static void test(void) {
  int *data;

  if (rand() % 2) {
    data = (int *)malloc(sizeof(int));
    if (!data)
      return;
    *data = 5;
  } else {
    data = (int *)malloc(sizeof(int));
    if (!data)
      return;
    *data = 5;
  }

  if (rand() % 2) {
    printf("%d\n", *data); // 수정 전: might be uninitialized
  } else {
    printf("%d\n", *data); // 수정 전: might be uninitialized
  }
}

int main(void) {
  test();
  return 0;
}
```

두 출력 지점에 도달하는 경로에서는 할당 성공을 확인했고, `*data = 5`도
실행됐다. 따라서 두 읽기의 미초기화 경고는 오탐이다.

**이 원본 예제는 수정 완료했다. `--opt=basic`과 `--opt=none` 모두
두 printf의 UVA 경고가 2건에서 0건으로 줄었다.** 한쪽 분기에서 초기화를
제거하면 경고는 유지된다.

사용자가 별도로 만든 `bench/branch_malloc_bench.c`는 함수 호출, 배열 루프,
`calloc`, `free` 등을 포함하는 추가 벤치마크다. 이 문서는 원본의 수정과
추가 벤치마크의 보완을 함께 기록한다. **추가 벤치마크 전체 또는 free 관련
분석까지 해결됐다는 의미는 아니다.**

이번 변경은 기존 `uva`를 사용한다. 새 checker나 활성화 옵션은 추가하지 않았다.

## 근본 원인

### 원인 1 — 포인터가 선택한 객체와 초기화 상태 사이의 관계 소실

**파일:** `core/include/ikos/core/domain/memory/value.hpp`

**함수:** `ValueDomain::join_with()`, `mem_read()`

**파일:** `core/include/ikos/core/domain/memory/value/cell_set.hpp`

두 `malloc`은 서로 다른 할당 지점의 메모리 객체로 표현된다.

```text
첫 번째 분기: data → 객체 A, A의 int 영역은 initialized
두 번째 분기: data → 객체 B, B의 int 영역은 initialized
```

`ValueDomain`은 스칼라 값, 메모리 셀, 포인터 집합, 객체 수명을 각각 합류한다.
셀 집합의 합류는 양쪽에 공통으로 존재하는 셀을 유지하며, 스칼라 분리 도메인에서
한쪽에 없는 정보는 TOP으로 합쳐진다.

따라서 합류 후에는 `data → {A, B}`라는 정보가 남아도,
**A가 선택된 경로에서는 A가 초기화됐고, B가 선택된 경로에서는 B가 초기화됐다는
관계**를 표현하지 못한다. 이후 읽기는 각 후보의 불확실한 셀 상태를 합쳐
초기화 여부가 불확실한 값을 반환한다.

이는 메모리 도메인의 관계 표현 정밀도 한계다. 한쪽 분기에만 있는 셀을
항상 초기화 상태로 남기는 변경은, 실제로 초기화가 누락된 다른 프로그램의
경고를 없앨 수 있으므로 적용하지 않았다.

### 원인 2 — 첫 보정에서 함수 호출과 할당 모델의 증명 범위 부족

첫 보정은 읽기 지점에서 LLVM 명령을 역추적해 초기화 저장을 찾았다.
이 방식으로 원본의 직접 `rand()` 호출 사례는 해결됐지만, 추가 벤치마크에는
다음과 같은 차이가 있었다.

| 추가 사례 | 첫 보정에서 놓친 이유 |
|---|---|
| G01·F04의 `coin()` | 직접 `rand()`만 허용해, 래퍼 호출에서 증명 중단 |
| G07의 `calloc` | 명시적인 store가 없는 0 초기화 할당을 증명하지 못함 |
| K02의 `alloc_init(value)` | 반환 포인터와 초기화에 사용한 인수의 관계를 따라가지 못함 |
| G10의 callee 읽기 | 형식 포인터 인수를 실제 호출자의 메모리와 연결하지 못함 |
| B02의 양쪽 미초기화 | 초기화 증명만 있어, 확정 미초기화 정보를 복구하지 못함 |

최종 구현에는 이 항목들의 후속 보완을 포함한다.

## 수정 내용

### 수정 1 — 읽기 지점의 초기화·미초기화 보조 증명 추가

**새 파일:** `analyzer/include/ikos/analyzer/analysis/initialization.hpp`

**새 파일:** `analyzer/src/analysis/initialization.cpp`

`InitializationProof`와 다음 두 진입점을 추가했다.

```cpp
bool prove_initialized_load(ar::Load* load, CallContext* context);
bool prove_uninitialized_load(ar::Load* load, CallContext* context);
```

AR load에 연결된 LLVM load를 출발점으로, 읽는 주소와 바이트 크기를 추적한다.
제어 흐름의 각 선행 경로를 역으로 확인하며, PHI 포인터는 해당 선행 간선의
실제 포인터로 치환한다.

- 초기화 증명은 읽는 영역 전체를 덮는 초기화된 저장 또는 지원하는 0 초기화
  할당을 확인한다. 일부 바이트만 쓴 것으로 전체 읽기를 초기화 판정하지 않는다.
- 미초기화 증명은 읽는 범위가 크기를 확인한 `malloc` 영역 안에 있고,
  그 영역이 쓰이지 않은 상태임을 모든 경로에서 확인한다.
- 한쪽은 초기화, 다른 쪽은 미초기화이면 두 확정 증명 모두 성립하지 않는다.
- 증명 함수가 `false`를 반환하면 해당 성질을 증명하지 못한 것이다.
  그 사실만으로 안전 또는 오류를 새로 판정하지 않는다.

일반 메모리 합류 연산은 유지하고, 읽기 결과의 초기화 상태를 보완하는 구조다.
읽은 정수·부동소수점의 수치 값을 새로 추론하는 기능은 추가하지 않았다.

### 수정 2 — 일반 메모리 읽기 결과에 증명 반영

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `NumericalExecutionEngine::exec(ar::Load*)`

기존 `mem_read()`를 먼저 수행한다. 비휘발성 스칼라 읽기 결과가 초기화로
확정되지 않은 경우에 보조 증명을 실행한다.

```cpp
if (!this->_inv.normal().uninit_is_initialized(lhs.var())) {
  if (prove_initialized_load(s, this->_call_context)) {
    this->_inv.normal().uninit_refine(lhs.var(),
                                     Uninitialized::initialized());
  } else if (prove_uninitialized_load(s, this->_call_context)) {
    this->_inv.normal().uninit_refine(lhs.var(),
                                     Uninitialized::uninitialized());
  }
}
```

두 성질 모두 증명하지 못하면 기존 읽기 결과를 유지한다.

기존 UVA checker가 보정 후 상태를 검사한다. printf 경고만 별도로
억제하는 처리는 추가하지 않았다. `volatile` 읽기, 벡터, 집약 값 전체의
읽기에는 이 보정을 추가하지 않았다.

### 수정 3 — opt=none의 포인터 재로드와 별칭 복사 추적

**파일:** `analyzer/src/analysis/initialization.cpp`

`none`에서는 지역 포인터가 스택 슬롯에 저장되고 반복해서 재로드된다.
슬롯이 외부로 노출되지 않았고 접근이 일반 load/store인 경우에만 슬롯의
내용을 상징적으로 추적한다.

재로드 사이에 슬롯이 변경될 수 있는지 확인하고, 역추적 중 슬롯 대입을 만나면
저장된 포인터로 주소를 치환한다. 이를 통해 `q = p` 같은 복사를 따라가면서,
재대입 전 포인터와 재대입 후 포인터를 같은 대상으로 취급하지 않도록 했다.

원래 LLVM 포인터 정의를 넘어 이전 루프 반복의 같은 명령을 현재 포인터로
사용하지 않으며, CFG 순환을 만나면 보수적으로 증명을 중단한다.

### 수정 4 — coin() 래퍼와 calloc 보완

**파일:** `analyzer/src/analysis/initialization.cpp`

**함수:** `preserves_memory()`, `initialized_allocation()`

`coin()`이라는 이름을 특별 취급하지 않는다. 함수 본문과 중첩 호출을 확인해
메모리를 보존하는지 검사한다. LLVM의 메모리 비접근·읽기 전용 속성과 기존
IKOS의 libc `rand` 모델을 사용하며, 메모리 쓰기나 불명확한 호출이 있으면
증명을 중단한다. 이 보완으로 추가 벤치마크 G01·F04의 UVA 오탐을 제거했다.

`calloc`은 상수 인수의 `count * size`를 계산하고, 곱셈 오버플로와 읽기 범위를
확인한다. 할당 범위 안의 읽기에 0 초기화 사실을 사용하여 G07을 보완했다.
임의의 외부 할당 함수를 `calloc`과 동일하게 처리하지 않는다.

### 수정 5 — 실제 호출 문맥으로 인수·반환 포인터 연결

**파일:** `analyzer/src/analysis/initialization.cpp`

**함수:** `in_caller()`, `argument_memory()`, `returned_memory()`, `initialized()`

- `CallContext`에 연결된 LLVM 직접 호출과 현재 함수를 정확히 대응시킨다.
- callee가 포인터 인수로 읽으면 실제 인수의 주소를 구해 호출 직전의
  caller 경로로 거슬러 올라간다. 이 보완으로 G10을 해결했다.
- 할당 래퍼의 반환 포인터는 함수의 반환 경로들을 확인한다.
  초기화 저장에 사용한 형식 인수도 해당 호출의 실제 값으로 연결해 K02를 해결했다.
- `none`에서 스택에 저장된 스칼라 인수는 외부로 노출되지 않은 슬롯과
  하나의 지배적인 저장을 확인하는 경우에만 전달한다.
- LLVM의 `noundef` 표시만으로 소스의 미초기화 인수를 초기화 상태로 간주하지 않는다.
- 지원하는 NULL 반환 경로의 제외는 유효한 메모리 읽기에 대한 증명이다.
  NULL 역참조의 안전성을 증명하는 기능은 아니며 관련 검사는 별도로 유지한다.

각 호출은 자신의 인수와 경로를 사용한다. 같은 reader를 초기화된 포인터와
미초기화된 포인터로 각각 호출해도 두 호출의 결과가 섞이지 않는 것을 확인했다.

### 수정 6 — B02를 확정 미초기화로 판정

**파일:** `analyzer/src/analysis/initialization.cpp`

**함수:** `untouched_allocation()`, `prove_uninitialized_load()`

양쪽 분기 모두 초기화 없이 `malloc` 결과를 읽는 B02는 기존 합류에서
확정 미초기화 정보가 사라져 `warning`으로 보고됐다.

읽는 영역이 크기를 확인한 `malloc` 안에 있고 아직 쓰이지 않았음을 모든
경로에서 증명하면 읽기 결과를 미초기화로 정제한다. 이 보완으로 B02는
`error`가 된다. 부분 쓰기나 추가 쓰기 때문에 손대지 않은 영역임을
확인할 수 없으면 확정 증명을 중단한다.

한쪽만 초기화한 B01·B03~B05의 `warning`은 유지됐다.

### 수정 7 — 빌드 대상 등록

**파일:** `analyzer/CMakeLists.txt`

`src/analysis/initialization.cpp`를 `ikos-analyzer`의 소스 목록에 추가했다.
메모리 도메인의 합류 구현, `exec_free()`, BOA·DFA checker는 변경하지 않았다.

## 검증

프로젝트에 새 회귀 테스트 파일이나 실행 스크립트는 추가하지 않았다.
임시 디렉터리에서 빌드와 정적 분석을 수행했으며, 벤치마크 프로그램을
실행해 결과를 확인하는 방식은 사용하지 않았다.

- 원본 예제: `basic`·`none`에서 UVA 경고 2건 제거 확인.
- 추가 벤치마크: 두 설정에서 위 표의 결과 확인.
- 앞선 보완 사례 23개 × 2개 설정: **46개 분석 통과**.
  초기화 누락, 부분 쓰기, 다른 원소·필드 읽기, 포인터 재대입 등의 진단을 확인했다.
- 함수 경유 사례 24개 × 2개 설정: **48개 분석 통과**.
  인수 전달, 중첩 reader, 할당 래퍼, NULL 반환, 초기화 누락·부분 초기화,
  미초기화 인수, 별칭 재대입, 중간 덮어쓰기를 확인했다.
- 호출 문맥 분리 사례 × 2개 설정: **2개 분석 통과**.
  같은 reader의 안전한 호출과 오류 호출을 각각 유지했다.
- 위 임시 보완 검증은 합계 **96개 분석**이다.
- 실행 가능한 기존 UVA 테스트 **33개 통과**.
  `test-33-error.cpp`, `test-34-safe.cpp`, `test-35-safe.cpp`, `test-36-error.cpp`는
  기존 LLVM importer의 `unexpected llvm constant expression` 오류로 제외했다.
  UVA 전체 테스트를 모두 통과했다는 의미는 아니다.
- 기존 `analysis-memory`, `analysis-double-free`, `analysis-division-by-zero`
  테스트 그룹 통과.

## 남은 문제와 적용 한계

### G06 — 배열 루프 초기화

**파일:** `core/include/ikos/core/domain/memory/value.hpp`

**함수:** `write_realize_range_cells()`

```c
int *arr = malloc(4 * sizeof(int));
if (!arr)
  return;
for (int i = 0; i < 4; ++i)
  arr[i] = i;
printf("%d\n", arr[2]); // 남은 UVA warning
```

분기를 제거하고 할당 지점 하나로 줄여도 재현됐다. 범위 인덱스 쓰기에서
겹치는 셀의 정보를 버리는 경로가 있으며, 반복 중 `[0, i)`가 초기화되고
정상 종료 후 `[0, 4)`가 초기화된다는 정보를 유지하지 못한다.

이번 보조 증명도 루프를 요약하거나 반복 횟수·배열 구간을 증명하지 않는다.
이 문제는 배열 구간의 초기화 추적 또는 루프 요약 등 도메인 확장이 필요하다.
중간 종료·조건부 쓰기·부분 초기화의 차이를 보존해야 하므로, 루프에 store가
있다는 사실만으로 전체 배열을 초기화 판정하는 변경은 적용하지 않았다.

### free — 선택된 객체와 수명 사이의 상관관계

**파일:** `core/include/ikos/core/domain/memory/value.hpp`

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `join_with()`, `exec_free()`

분기 합류에서 한쪽에만 존재하는 객체의 수명도 불확실해진다.
또한 `exec_free()`는 포인터의 대상이 하나면 해제 상태로 대입하지만,
대상이 여러 개면 각 후보에 `lifetime_forget()`을 적용한다.

따라서 다음과 같은 한계가 남아 있다.

- 정상적인 첫 free에도 가능한 이중 해제 경고가 발생한다.
- 실제 이중 free 또는 양쪽 경로의 해제 후 사용을 확정 error로 판정하지 못한다.
- 해제한 경로가 return하는 정상 사례에도 수명 관련 경고가 남는다.

가능한 대상 전부를 무조건 해제 상태로 바꾸면 실제로 선택되지 않은 객체도
해제된 것으로 취급하게 된다. 선택된 포인터와 해당 객체의 할당·해제 상태를
함께 보존하는 별도 개선이 필요하다. **이번 변경은 free 수명 추적을 수정하지 않았다.**

### 보조 증명의 범위

- LLVM frontend 정보가 있는 일반 스칼라 load를 대상으로 한다.
- 간접 호출의 대상이 불명확하거나 실제 호출 문맥을 연결할 수 없으면
  해당 호출의 인수 관계를 추측하지 않는다.
- 복잡한 별칭, 외부로 노출된 로컬 슬롯, 불명확한 메모리 변경,
  volatile·atomic 접근 등은 증명 범위 밖이거나 보수적으로 중단한다.
- 초기화된 저장 값의 확인도 지원하는 상수, 인수 연결, 제한된 로컬 슬롯,
  기존 rand 모델 등에 한정한다. 임의의 수치 식을 모두 판별하지 않는다.
- 각 증명의 공유 작업 예산은 1024이며, CFG 역추적 깊이 32와 함수 프레임
  전환 깊이 8 등의 제한을 둔다. 순환이나 제한 초과 시 증명 실패로 처리한다.
- 이미 초기화로 판정된 모든 메모리 읽기를 재검사하는 기능이나,
  전체 힙 분석의 관계 표현을 바꾸는 수정은 추가하지 않았다.

따라서 완료 범위는 **원본의 미초기화 오탐 수정과 위 표에서 확인한 UVA 보완**이다.
배열 루프와 free까지 포함한 전체 문제의 완료로 기록하지 않는다.

## 빌드 및 재확인

임시 검증 빌드와 설치된 `ikos-fixed2`는 별개다. 소스를 다시 빌드·설치한다.

```sh
/Applications/CLion.app/Contents/bin/ninja/mac/aarch64/ninja \
  -C /Users/baesungmin/Projects/ants/ikos2/cmake-build-debug -j4 install
```

UVA 결과를 먼저 확인한다.

```sh
cd /Users/baesungmin/Projects/ants/ikos2
ikos-fixed2 -a=uva --opt=basic -o bench/branch-uva-basic.db bench/branch_malloc_bench.c
ikos-fixed2 -a=uva --opt=none -o bench/branch-uva-none.db bench/branch_malloc_bench.c
```

수명·버퍼 검사 결과는 함께 실행해서 별도로 확인할 수 있다.

```sh
ikos-fixed2 -a=uva,dfa,boa --opt=basic -o bench/branch-all-basic.db bench/branch_malloc_bench.c
ikos-fixed2 -a=uva,dfa,boa --opt=none -o bench/branch-all-none.db bench/branch_malloc_bench.c
```

벤치마크는 `argc`의 switch로 사례를 분리하므로 특정 `--argc` 값은 지정하지 않는다.
B 그룹의 실제 오류와 미해결 사례가 포함돼 있으므로 전체 보고서의 `SAFE` 여부보다
검사기·함수·해당 읽기 위치별 결과를 위 표와 비교한다.
