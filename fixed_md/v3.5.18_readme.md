# IKOS 3.5.18 — `!= 0` 검사로 보호된 정수 나눗셈

## 문제 요약

```c
int data = -1;
fscanf(stdin, "%d", &data);
if (data != 0) {
    printIntLine(100 / data);   /* warning: divisor might be zero */
}
```

구간(interval) 도메인은 "0 을 뺀 모든 값"을 표현할 수 없다. `data` 가 `[MIN, MAX]` 이면
`data != 0` 을 가정해도 구간은 그대로 `[MIN, MAX]` 이고, 0 이 남아 경고가 나온다.

Juliet CWE369 int `*_divide`/`*_modulo` 의 goodB2G(`goodB2G`, `goodB2G1`, `goodB2G2`)가
모두 이 형태다. v3.5.16 Linux 기준 good FP 636건(divide/modulo 각각 goodB2G 168 +
goodB2G1·goodB2G2 각 75)이고, 그중 112건은 v3.5.4 에서 원래 가려져 있던 것이 드러난
것이다. 특정 수정 단계의 부작용이 아니라 도메인 표현력 문제라 별도 버전으로 다룬다.

## 수정

**파일:** `analyzer/src/checker/division_by_zero.cpp` — `IntDivisorProof`, `guarded_nonzero()`

정수 제수의 구간에 0 이 들어 있을 때, 경고하기 전에 LLVM 코드에서 다음을 증명한다.
(float 제수에 이미 쓰던 `FloatDivisorProof` 와 같은 방식이다.)

1. 함수 안의 조건 분기 `icmp pred x, C` 중에서 `x == 0` 이면 거짓이 되는 쪽 간선
   (`!= 0`, `> 0`, `== 0` 의 거짓 쪽 등, 비교를 0 으로 상수 계산해 결정)이
   나눗셈 블록을 지배(dominate)해야 한다.
2. 비교한 `x` 와 제수가 같은 값이어야 한다.
   - 같은 SSA 값. 비교 쪽은 sext/zext/trunc, 제수 쪽은 sext/zext 까지 벗긴다.
     어느 쪽이든 "앞의 값 ≠ 0 ⇒ 뒤의 값 ≠ 0" 이 성립하는 변환만 벗긴다.
   - 또는 같은 포인터를 단순 load 로 두 번 읽었고, 두 load 사이가 단일 선행 블록
     사슬(최대 8개)이며 그 사이에 메모리를 쓰는 명령(호출 포함)이 없다.

증명되면 결과는 `ok` 다. 다음 경우는 증명하지 않으므로 경고가 그대로 남는다.

- 검사 뒤 값을 다시 쓰는 경우
- 검사의 반대쪽 분기, 합류 지점 뒤
- 다른 변수를 검사한 경우, 잘라낸 값으로 나누는 경우
- `>= 0`, `!= 1`, `||` 로 묶인 조건
