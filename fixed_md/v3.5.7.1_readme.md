# IKOS 3.5.7.1 — (v3.5.7 연장) 상수 문자열의 종료 문자 판정

## 문제 요약

v3.5.7 은 `printf("%s", ...)` 등에서 문자열이 NUL 로 끝나는지 검사한다. 이 검사는
형식 문자열 자체(`"%d\n"`)에도 적용된다. 그런데 분석 중 메모리 정보가 통째로
지워지면(예: libstdc++ `std::map` 내부의 재귀 호출 → `mem_forget_all`) 바뀔 수 없는
**상수 문자열의 내용까지** 잊어, 다음 오탐이 발생했다.

```text
io.c:29: possible buffer overflow, pointer '&"%d\n"[0]' accesses between 1 and 5 bytes
         ... of constant "%d\n" of size 4 bytes
```

Juliet (Linux, v3.5.6 → v3.5.7) CWE126 `_74`(std::map) 에서 FP 18개와,
같은 원인의 경고가 bad 에 떨어진 "우연한 TP" 12개가 생겼다.

---

## 근본 원인

**파일:** `analyzer/src/checker/buffer_overflow.cpp` — `string_read_size()`

종료 문자 위치를 분석 상태의 메모리에서 한 바이트씩 읽어 찾았다. 상수 전역이라도
메모리 상태가 지워지면 바이트 값을 몰라 "끝을 못 찾을 수 있음"이 됐다.

---

## 수정

읽는 대상이 하나의 전역이고, 그 LLVM 전역이 `constant` 이며 확정 초기값
(`hasDefinitiveInitializer`)을 가지면, 메모리 상태 대신 **초기값에서 직접**
읽기 시작 오프셋부터 첫 NUL 까지의 길이를 구한다. 상수 전역은 실행 중 바뀔 수 없으므로
(쓰기는 UB) sound 하다. 1바이트 원소 배열(`ConstantDataSequential`)과
`zeroinitializer` 를 지원하며, NUL 이 없으면 기존 방식으로 처리한다.

---

## 수정 결과

- Linux `std::map` 예제: sink 의 `printf("%d\n", ...)` 형식 문자열 경고 사라짐.
- v3.5.7 원래 대상(NUL 없는 지역 배열을 `%s` 로 출력 → error)과 후속 예제들은 그대로.
- 기존 예제 90여 개 중 바뀐 것은 위 1건뿐.
