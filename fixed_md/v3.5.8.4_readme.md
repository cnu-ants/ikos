# IKOS 3.5.8.4 — (v3.5.8 연장) 작은 정수 타입과 C++ `abs` 오버로드의 절댓값 검사

## 문제 요약

v3.5.10.2 로 char/short 산술 결과의 범위 초과를 검사하면, square good 의 다음 검사가
인식되지 않아 good 이 FP 가 된다.

```c
char data;                                           /* fscanf 입력 */
if (abs((long)data) <= (long)sqrt((double)CHAR_MAX)) {
    char result = data * data;                       /* -11..11 이면 안전 */
}
```

두 가지 이유가 있다.

1. **C**: IR 에서 `abs(trunc(sext i8 data to i64) to i32)` 다.
   - 이 값은 INT_MIN 이 될 수 없는데도 MIN 제외 검사가 없다고 보고 상한만 넣었다(v3.5.8.2).
   - 범위가 변환된 i32 값에만 걸려, 곱셈에서 다시 읽은 `data` 에는 전달되지 않았다.
2. **C++**: `abs((long)data)` 가 `<cstdlib>` 의 C++ 오버로드로 호출된다. 절댓값 함수로
   인식되지 않았다.
   - libc++: `_Z3absl`, 헤더 inline 정의
   - libstdc++: `_ZSt3absl` = `std::abs(long)`

---

## 수정

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

1. `guard()`: 절댓값 입력이 sext 이거나, sext 를 원래 폭 이상으로 자른 값이면 원래의
   좁은 값 c 와 값이 같고 그 타입의 MIN 이 될 수 없다. 그래서 양쪽 범위 `-M <= c <= M` 을
   **c 자체**에 넣는다. M 이 c 의 signed 최댓값 이상이면 배울 것이 없으므로 그대로 둔다.
2. `integer_abs()`: C++ `abs(long)`/`abs(long long)` 오버로드(`_Z3absl`, `_Z3absx`,
   `_ZSt3absl`, `_ZSt3absx`)도 절댓값으로 인식한다.
   - 선언이거나 표준 헤더의 inline 정의(`linkonce_odr`/`available_externally`)일 때만 받는다.
   - 의미는 `labs`/`llabs` 와 같고, 프로그램이 이 함수를 다시 정의할 수 없다.
   - MIN 이 들어오는 경우는 IKOS 가 inline 본문의 `-x` 를 분석하며 overflow 로 보고한다.

호출과 원래 조건은 그대로 둔다.

## 수정 결과

이 버전만으로는 Juliet 판정 변화가 없다. char/short 산술 검사는 v3.5.10.2 에서
추가되기 때문이다. v3.5.10.2 와 함께 확인한 결과(Mac 하네스, CWE190 char/short square):

| char square good FP (fscanf/max/rand 합계, short 도 같음) | 개수 |
|---|---|
| v3.5.10.2 만 | 94 |
| + 수정 1 (작은 타입 abs 입력) | 18 (C++ `_33`·`_43`·`_62` 9 + STL 9) |
| + 수정 2 (C++ abs 오버로드) = v3.5.8.4 | 9 (`_72`~`_74` STL 만) |

- Linux 형태(`-fmath-errno`), x86_64 libstdc++ 형태(`_ZSt3absl`) 예제에서도 good 경고가
  없고, 검사 없는 bad 는 경고한다.
- int/int64 square 결과와 기존 예제 회귀 스위트는 변화가 없다.
