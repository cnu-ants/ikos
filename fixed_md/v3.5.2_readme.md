# IKOS 3.5.2 — operator[], insert 이후 분석 결과가 사라지는 문제 수정

## 문제

`std::map::operator[]`, `std::map::insert` 등 STL 연산 후 그 이후의 모든 분석 결과가 사라지는 버그.

```cpp
std::map<int, int> m;
m[0] = 1;             // 이 이후 분석 결과 없음 ← 버그

int z = 0;
printf("%d\n", 1/z);  // 검출 안 됨
```

---

## 원인

두 개의 독립된 경로에서 분석 상태가 bottom(도달 불가)이 됐다.

### 원인 1 — `undef` store → 전역 초기화 단계에서 bottom

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

STL 헤더의 전역 상수(`std::piecewise_construct` 등)가 LLVM IR에서 `undef`로 초기화된다.
기존 코드는 `undef`가 포함된 store를 포인터/값 구분 없이 무조건 `set_normal_flow_to_bottom()`으로 처리했다.
결과적으로 `main()` 진입 전 전역 초기화 단계에서 이미 분석 상태가 bottom이 되어 이후 모든 코드가 unreachable 처리됐다.

### 원인 2 — `__find_equal` while(true) 루프 → STL 반환 시 bottom 전파

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/inliner.hpp`

`operator[]`, `insert` 등은 내부적으로 rb-tree 탐색 함수 `__tree::__find_equal`을 호출한다.
이 함수는 `while(true)` 루프로 구현되어 있는데, 추상 해석 중 widening 후 fixpoint가 `normal=⊥`로 수렴한다.
이 bottom이 호출 체인을 따라 역으로 전파되어 사용자 코드에서의 STL 호출이 `normal=⊥`를 반환하고, 이후 코드 전체가 unreachable 처리됐다.

---

## 수정

### 수정 1 — `undef` 값 store 처리 분리

저장 **포인터**가 `undef`인 경우는 UB로 처리(기존 유지), 저장 **값**이 `undef`인 경우는 대상 메모리를 `mem_forget_reachable`로 TOP 처리.

```cpp
// 수정 전: 포인터/값 구분 없이 무조건 bottom
if (s->has_undefined_constant_operand()) {
    this->_inv.set_normal_flow_to_bottom();
    return;
}

// 수정 후
if (isa< ar::UndefinedConstant >(s->pointer())) {
    this->_inv.set_normal_flow_to_bottom();  // 포인터 undef → UB, bottom 유지
    return;
}
if (isa< ar::UndefinedConstant >(s->value())) {
    // 값 undef → 해당 메모리 셀을 forget(TOP), 분석 계속
    this->_inv.normal().mem_forget_reachable(ptr.var(), size);
    return;
}
```

### 수정 2 — STL callee가 bottom 반환 시 fallback 적용

사용자 코드 → STL 경계에서 STL callee의 분석 결과가 `normal=⊥`일 때, `exec_unknown_extern_call`을 fallback으로 적용해 분석 흐름을 유지.
STL → STL 내부 호출에는 적용하지 않음(분석 폭발 방지).

```cpp
// STL 함수 여부 판별 (Itanium ABI mangling 기준)
// _ZNSt: std:: 멤버, _ZNKSt: std:: const 멤버, _ZSt: std:: 비멤버 함수
static bool is_std_function(ar::Function* f);

// STL callee가 normal=⊥를 반환한 경우
if (engine.inv().is_normal_flow_bottom()) {
    if (!caller_is_std && is_std_function(callee)) {
        // 사용자 → STL 경계: fallback으로 분석 흐름 유지
        NumericalExecutionEngineT fallback = this->_engine.fork();
        fallback.exec_unknown_extern_call(call);
        post.join_with(std::move(fallback.inv()));
    } else {
        post.join_with(std::move(engine.inv()));
    }
    continue;
}
```

## 결과

| 케이스 | 수정 전 | 수정 후 |
|--------|---------|---------|
| STL 연산 후 SENTINEL 검출 | 검출 안 됨 | error |
| vector/list 원소 0 넣고 나누기 | 검출 안 됨 | error |
| std::fill/copy 후 나누기 | 검출 안 됨 | warning |
| unordered_map, deque 등 | 검출 안 됨 | error |

### 한계

STL 연산의 반환값 추적은 불가. `exec_unknown_extern_call` fallback이 반환값을 TOP으로 처리하기 때문에, `m[0] = 5` 후 `m[0]`을 읽어도 값이 5임을 알 수 없다. STL 연산 이후 흐름을 살리는 것이 이번 수정의 범위이며, 반환값 추적은 별도 작업이 필요하다.
