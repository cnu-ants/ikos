# IKOS 3.5.105 — 절댓값·제곱근 조건의 정수 범위 전파 및 오버플로 오탐 수정

## 문제 요약

`imaxabs()`와 `sqrtl()`로 제곱 연산의 범위를 검사해도, IKOS가 조건의 의미를
정수 변수의 범위에 반영하지 못해 signed integer overflow를 보고했다.

```c
#include <inttypes.h>
#include <limits.h>
#include <math.h>
#include <stdint.h>
#include <stdio.h>

static void test(void) {
  int64_t data = LLONG_MAX;
  if (imaxabs((intmax_t)data) <= sqrtl(LLONG_MAX)) {
    int64_t result = data * data;  // 수정 전: signed integer overflow error
    printf("%" PRId64 "\n", result);
  }
}

int main(void) {
  test();
  return 0;
}
```

위 예제에서는 조건이 거짓이므로 곱셈에 도달하지 않는다. 문제는 곱셈을
안전한 연산으로 바꾸는 것이 아니라, 실행되지 않는 곱셈에 오류를 보고하는 것이다.

최초 부분 수정에서는 상수로 비교 결과를 증명하는 전처리 패스를 추가하여
위 예제의 오탐을 제거했다. 그러나 입력값을 모르는 아래 형태에서는 경고가 남았다.

```c
int64_t d = any64();  // 분석기 입장에서 값이 정해지지 않은 입력
if (d != INT64_MIN && imaxabs((intmax_t)d) <= sqrtl(LLONG_MAX)) {
  int64_t result = d * d;  // 부분 수정 후에도 possible signed overflow
}
```

사용자 벤치마크를 확인한 결과, 상수 입력 G01·G07·G12는 통과했지만
G02~G06·G08~G11의 안전 사례 9개에 오탐이 남아 있었다.
현재 확인한 파일은 `bench/test.c`이며, 사용자가 `test2.c`로 설명한
K/G/B/C 그룹과 같은 사례가 들어 있다.

이번 변경은 상수 비교 처리와, 위 9개 오탐을 해결하기 위한 후속 보완을 함께 포함한다.
`--opt=basic`과 `--opt=none` 모두를 대상으로 한다.

## 근본 원인

### 원인 1 — 정수 절댓값 함수의 수치 모델 부재

**파일:** `frontend/llvm/src/import/library_function.cpp`

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

기존 importer는 `abs()`만 `LibcAbs`로 인식했고,
`labs()`·`llabs()`·`imaxabs()`는 절댓값 함수로 모델링하지 않았다.
인식된 `LibcAbs`도 실행 엔진에서 `exec_unknown_call()`로 처리했다.

```cpp
case ar::Intrinsic::LibcAbs: {
  this->exec_unknown_call(call,
                         /* may_write_params = */ false,
                         /* ignore_unknown_write = */ false,
                         /* may_write_globals = */ false,
                         /* may_throw_exc = */ false);
} break;
```

따라서 표현 가능한 입력에 대한 절댓값 결과가 음수가 아니라는 사실조차 남지 않았다.
이 문제는 부동소수점 연산이 없는 G08·G09·G10에도 영향을 주었다.

예를 들어 G08의 `a <= 3037000499` 분기에서는 다음 차이가 확인됐다.

```text
실제 필요한 범위: a ∈ [0, 3037000499]
기존 분석한 범위: a ∈ [INT64_MIN, 3037000499]
```

음수 쪽의 큰 값이 제곱 연산의 후보로 남아 underflow/overflow 경고가 발생했다.

### 원인 2 — 실수 변환과 비교에서 수치 정보가 연결되지 않음

**파일:** `analyzer/src/analysis/literal.cpp`

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

분석기의 기존 부동소수점 표현에는 다음 한계가 있다.

- `FloatConstant`는 수치 정보를 담지 않는 `DummyNumber`로 변환된다.
- `exec_int_to_float_conv()`는 결과를 `float_assign_nondet()`으로 처리한다.
- `exec_float_comparison()`는 초기화 여부만 확인하고 수치 범위를 제한하지 않는다.

따라서 정수에서 실수로 변환한 절댓값과 제곱근을 비교해도,
조건이 거짓임을 알아내거나 원래 정수 입력의 범위를 좁히지 못했다.

이번 변경이 위 함수들에 일반적인 부동소수점 도메인을 구현한 것은 아니다.
지원하는 계산에 한해 LLVM 전처리 단계에서 증명 가능한 정보를 보완한다.

### 원인 3 — 절댓값 결과의 조건이 원래 입력으로 역전파되지 않음

G11은 실수 연산 없이 `abs(x) < 46341`로 검사하지만, 곱셈은 결과가 아닌
원래 입력 `x`를 사용한다.

```c
if (x != INT_MIN && abs(x) < 46341) {
  int result = x * x;
}
```

절댓값 결과를 `[0, INT_MAX]`로 모델링하는 것만으로는 충분하지 않다.
`abs(x) < 46341`에서 `-46340 <= x && x <= 46340`이라는 정보를
원래 입력에 전달해야 곱셈의 안전성을 판정할 수 있다.

## 수정 내용

### 수정 1 — 절댓값 계열을 입력 정수 폭에 맞게 모델링

**파일:** `ar/src/semantic/intrinsic.cpp`

**파일:** `frontend/llvm/src/import/library_function.cpp`

기존 32비트 `abs()` 모델을 유지하면서, `LibcAbs`에 정수 타입 매개변수를 지원했다.
`labs()`·`llabs()`·`imaxabs()`는 선언의 반환형과 인수형을 확인하여
해당 폭의 signed integer 절댓값 intrinsic으로 가져온다.
인수 개수·타입이 맞지 않거나 가변 인수 선언이면 이 모델을 적용하지 않는다.

호스트의 `long` 크기를 하드코딩하지 않고 LLVM 선언에 나타난 정수 폭을 사용한다.

### 수정 2 — 표현 가능한 abs 결과의 범위 계산

**파일:** `analyzer/include/ikos/analyzer/analysis/execution_engine/numerical.hpp`

**함수:** `exec_abs()`

`LibcAbs`의 unknown 처리를 전용 모델로 교체했다.

| 입력 상태 | 결과 처리 |
|-----------|-----------|
| 최소 signed 값이 아닌 상수 | 정확한 절댓값 대입 |
| 입력 전체가 0 이상 | 입력을 결과로 대입 |
| 입력 전체가 음수이며 최소 signed 값 제외 | `0 - 입력`으로 계산 |
| 양수·음수가 섞이고 최소 signed 값 제외 | `[0, max(-입력 하한, 입력 상한)]` |
| 최소 signed 값이 가능 | 임의의 결과를 유지 |

`abs(INT_MIN)`처럼 양수 결과를 같은 타입에 표현할 수 없는 경우에
무조건 `[0, MAX]`를 부여하거나 분석 경로를 제거하지 않는다.
그 경우를 직접 진단하는 기능은 이번 변경에 포함하지 않았다.

이 모델로 G08·G09·G10에서 필요한 비음수 결과 범위가 보존된다.

### 수정 3 — 지원하는 상수 실수 비교의 참·거짓 증명

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

`ProveConstantFloatComparisonPass`를 추가했다.
LLVM의 `APInt`·`APFloat`로 지원하는 정수 상수, 절댓값, 수치 변환,
유한한 실수 상수와 `llvm.sqrt`의 범위를 계산한다.

비교 결과가 확정될 때만 비교의 사용처를 참 또는 거짓으로 대체한다.
원래 호출·변환·산술 명령은 삭제하지 않으며 별도의 DCE를 추가하지 않는다.
비교 이전에 실행되는 오류 연산을 함께 지워서 진단이 사라지지 않도록 한다.

원래 예제에서는 조건이 거짓으로 증명되어, 곱셈이 실행되는 경로가 제거된다.
이는 곱셈 자체를 안전하다고 가정하는 처리가 아니다.

### 수정 4 — 제곱근 범위와 정수→실수 반올림 고려

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

**함수:** `bounds()`, `guard()`

제곱근은 호스트의 `sqrt()`·`long double`로 계산하지 않는다.
먼저 정수 제곱근으로 범위를 감싸고, IEEE half/float/double에서는
실제 근을 감싸는 인접한 표현 가능 값까지 범위를 좁힌다.
후보 값의 제곱 비교에는 이 형식들의 제곱을 정확히 표현할 수 있는
IEEE quad 연산을 사용한다.

다음으로 정수 크기를 해당 실수 형식으로 변환했을 때의 반올림 결과를 비교하여,
조건이 허용할 수 있는 정수 크기의 상한을 이진 탐색한다.
실수 임계값을 단순히 정수로 내리는 방식은 사용하지 않는다.

이 처리가 필요한 이유는 큰 정수를 `float` 등으로 변환할 때 서로 다른 여러 정수가
같은 실수 값으로 반올림될 수 있기 때문이다. 이런 경우에도 허용 가능한 정수를
잘못 제외하여 실제 오버플로 경고를 없애지 않도록 했다.

### 수정 5 — 원래 조건을 유지하며 정수 입력 범위 보강

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

**함수:** `guard()`, `strengthen()`

지원하는 정수 절댓값 비교 또는 실수 비교가 참인 경로에,
그 조건으로부터 반드시 성립하는 정수 범위 검사를 추가한다.

```text
원래 조건이 참
    ↓
입력 <= 증명한 상한
    ↓
입력 >= -증명한 상한
    ↓
원래 조건문의 본문
```

G02~G04에서는 `-3037000499 <= d <= 3037000499`,
G05·G11에서는 `-46340 <= x <= 46340`이라는 제약을 전달할 수 있다.
G06의 `fabs((double)d)` 조건도 지원하는 형태에 포함된다.

원래 수학 함수 호출과 비교를 유지한다. 따라서 추가한 정수 범위 조건만으로
원래 조건이 참이라고 단정하지 않는다.
다른 변수의 검사, 곱셈 이후의 검사, 느슨한 상한은 해당 곱셈을 안전하게 만들지 않는다.

정수 `abs`를 사용하는 이 보강은 최소 signed 입력이 제외되었음을 확인할 때만 적용한다.
최소값과의 동등·비동등 비교 및 그 분기의 지배 관계, 또는 확정된 비최솟값을 확인한다.

### 수정 6 — none의 재로드와 제어 흐름 처리

**파일:** `frontend/llvm/src/pass/prove_constant_float_comparison.cpp`

**함수:** `resolve()`, `minimum_excluded()`, `strengthen()`

`--opt=none`에서 지역 변수가 메모리에 남아 있어도, 주소가 노출되지 않은
직접 alloca에 단 하나의 단순 store가 있고 그 store가 읽기를 지배하면
저장된 값으로 연결한다.

volatile·atomic 접근, 별칭을 만드는 cast/GEP, 주소 노출, 여러 store가 있으면
이 연결을 적용하지 않는다. 임의의 반복 load를 같은 값으로 가정하지 않는다.

추가 범위 검사는 새 기본 블록에 배치하고, 원래 참·거짓 도착 블록의 PHI를 갱신한다.
지배 관계를 사용하는 계획은 CFG를 수정하기 전에 모두 수집한다.

### 수정 7 — 패스 등록과 실행 파이프라인 연결

**파일:** `frontend/llvm/CMakeLists.txt`

**파일:** `frontend/llvm/include/ikos/frontend/llvm/pass.hpp`

**파일:** `frontend/llvm/src/pass/initialize.cpp`

**파일:** `frontend/llvm/src/ikos_pp.cpp`

새 패스를 빌드·등록하고 LLVM Analysis 라이브러리를 연결했다.
기존 전처리 파이프라인 뒤, 검증 패스 앞에서 실행한다.
`none`·`basic`·`aggressive`에서 적용하며, `custom`에는 자동으로 추가하지 않는다.

## 검증

새 프로젝트 회귀 테스트 파일이나 실행 스크립트는 추가하지 않았다.
임시 작업 공간에서 빌드·검증하고, 기존 검사도 재실행했다.

- 기존 상수 처리 확인용 21개 사례를 두 옵션으로 분석한 42개 구성을 확인했다.
  실제 오류 진단은 유지됐으며, 개선된 제곱근 범위로 이전 경계값 오탐도 제거됐다.
- IEEE 비교 11,816개를 독립적인 정확한 유리수 계산과 대조했다.
  9,768개는 증명했고, 2,048개는 결과를 확정하지 않고 유지했다.
- 역방향 범위 전파 960개 형태에서 876개에 제약을 추가하고 84개는 유지했다.
  정수 변환과 조건에 관한 63,316개 함의를 정확한 유리수 계산으로 확인했다.
- 비교·수학 함수·환경에 따른 적용 조건 15개와,
  범위 보강의 적용 조건 및 PHI/CFG 처리 13개를 확인했다.
- 주소 노출 후 변경, volatile 재읽기, 다른 변수 검사, float 반올림,
  넓은 상한, 곱셈 뒤 검사, 양수·음수 절댓값의 후속 오버플로 등
  추가 오류 사례 8개를 두 옵션에서 계속 진단했다.

기존 검사 실행 결과는 다음과 같다.

| 검사 | 결과 |
|------|------|
| signed integer overflow | 7개 통과 |
| 메모리 | 52개 통과 |
| 관련 부동소수점·미초기화 | 25개 통과 |
| BOA 기존 실행 대상 | 128개 중 126개 통과, 기존 불일치 2개 동일 |

BOA의 불일치는 `test-23-safe.c`, `test-57.c`로 이전 수정 상태에서도 동일했다.
이 BOA 실행은 기존 importer 오류가 있던 `test-51.c`, `test-51-unsafe.c`,
`test-56.cpp`를 제외한 임시 실행 설정을 사용했다.
이 검증 결과가 분석기 전체의 건전성을 형식적으로 증명한다는 뜻은 아니다.

## 적용 범위와 남은 한계

- 일반적인 부동소수점 추상 도메인을 구현한 변경이 아니다.
  지원하지 않는 계산은 기존 분석에 남긴다.
- 동적 입력의 실수 가드 보강은 2~64비트 signed 정수의 `SIToFP`,
  IEEE half/float/double, 지원하는 절댓값 및 상한 비교 형태를 대상으로 한다.
  비교가 뒤집히거나 복합 연산으로 바뀌면 같은 정보를 얻지 못할 수 있다.
- `sqrt` 수치 처리는 상수 입력의 일반 `llvm.sqrt` intrinsic을 대상으로 한다.
  외부 호출로 남은 `sqrtl`, 실행 시 값이 정해지는 제곱근 입력, `pow` 등은 포함하지 않는다.
  현재 macOS ARM 환경에서는 벤치마크의 `sqrtl`이 `llvm.sqrt.f64`로 내려와 처리된다.
- 상수 제곱근 입력의 정수 경계 계산이 unsigned 64비트 범위를 벗어나면 적용하지 않는다.
- 80비트 확장 형식, NaN·무한대·음수 제곱근 등은 이 수치 증명의 대상에서 제외한다.
  근사 계산을 허용하는 fast-math 플래그·정밀도 메타데이터,
  strict FP 또는 지원하지 않는 FP 환경에서도 보강하지 않는다.
- `abs(MIN)`의 직접 진단은 별도 보완이 필요하다.
  이번 모델은 그 입력이 가능하면 결과를 임의의 값으로 유지한다.
- 별칭·메모리 쓰기 때문에 값의 동일성을 확인하지 못하면 재로드를 연결하지 않는다.
  임의의 참조·포인터·객체 필드에서 같은 정밀도를 보장하지 않는다.

## 빌드 및 재확인

기존 CMake 구성이 있는 `ikos2`에서 다시 빌드·설치한다.

```bash
/Applications/CLion.app/Contents/bin/ninja/mac/aarch64/ninja \
  -C /Users/baesungmin/Projects/ants/ikos2/cmake-build-debug -j4 install
```

`ikos-fixed2`가 위 설치 경로의 분석기를 사용하도록 설정된 상태에서 확인한다.
벤치마크는 컴파일·정적 분석만 수행하며 오류 사례를 직접 실행하지 않는다.

```bash
cd /Users/baesungmin/Projects/ants/ikos2
ikos-fixed2 -a=sio --opt=basic -o bench/math-basic.db bench/test.c
ikos-fixed2 -a=sio --opt=none  -o bench/math-none.db  bench/test.c
```

실제 파일명을 `test2.c`로 저장했다면 위 입력 경로를 그 파일명으로 바꾼다.
여러 사례를 선택하는 벤치마크이므로 전체 그룹 확인 시 `--argc`는 지정하지 않는다.
