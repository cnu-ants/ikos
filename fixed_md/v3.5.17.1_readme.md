# IKOS 3.5.17.1 — (v3.5.17 연장) 프로토타입 없는 함수 호출의 상수 반환 인식

## 문제 요약

v3.5.17 은 `if (globalReturnsTrue())` 처럼 상수만 돌려주는 함수의 조건 분기를 접는다.
Mac 에서는 CWE457 `_11` good FP 가 사라졌지만, **Juliet(Linux) 에서는 `_11` 이 그대로
남았다**(v3.5.18 기준 CWE457 `_11` good FP 36건).

Juliet 헤더는 이 함수를 프로토타입 없이 선언한다.

```c
int globalReturnsTrue();        /* std_testcase_io.h */
```

x86_64 Linux 에서 clang 은 프로토타입 없는 함수를 가변 인자 방식으로 호출한다.
`io.c` 의 정의(`i32 ()`)와 링크하면 호출이 bitcast 를 거친다. arm64 Mac 은 직접 호출이다.

```llvm
%3 = call i32 (...) bitcast (i32 ()* @globalReturnsTrue to i32 (...)*)()
```

`getCalledFunction()` 은 bitcast 를 거친 호출에 대해 null 을 돌려주므로 분기를 접지
못했다.

---

## 수정

**파일:** `frontend/llvm/src/pass/fold_constant_global_branches.cpp` — `evaluate()`

호출 대상의 포인터 cast 를 벗겨 정의를 찾는다. 다음 조건을 모두 만족할 때만 그 함수의
상수 반환값을 쓴다.

- 호출 쪽 인자가 없다.
- 함수 정의도 인자가 없다.
- 반환 타입이 호출 결과 타입과 같다.

---

## 수정 결과

x86_64 Linux 대상으로 컴파일해 `io.c` 와 링크한 예제:

| 예제 | v3.5.17 | v3.5.17.1 |
|---|---|---|
| `if (globalReturnsTrue())` 로 배열 초기화 후 읽기 (good) | warning | 경고 없음 |
| `if (globalReturnsFalse())` 로 초기화를 건너뛰고 읽기 (bad) | error | error |

Mac 결과(직접 호출)와 기존 예제 회귀 스위트는 변화가 없다. A/B 묶음에서 바뀐 것은
v3.5.15.1 의 `_17` 효과뿐이다.
